# День 14 — инварианты агента: установка и использование

День 14 — агент DeepSeek: FastAPI-бэкенд, Streamlit-интерфейс, SQLite и ключ
DeepSeek. Главная возможность дня — **инварианты проекта**: правила, которые агент
не имеет права нарушать. Правила лежат в отдельной таблице `invariants`, блоком
активных правил подставляются в системный промпт каждого запроса и проверяются
перед выдачей — сначала детерминированными правилами, при неоднозначности одним
вызовом LLM. Нарушение `hard`-инварианта превращается в отказ, `soft` — в
предупреждение. Эта инструкция покрывает установку и запуск, раздел
«📏 Инварианты», проверку текста, три сценария проверки и разбор отказа агента.
Полное описание приложения и всех его возможностей — в
[`README.md`](../README.md).

## 1. Требования и установка

Нужен **Python 3.14+**. Все команды выполняются из папки дня в PowerShell.

```powershell
cd day14
uv sync
copy .env.example .env      # затем впишите DEEPSEEK_API_KEY=sk-...
```

Менеджер зависимостей — **uv**: прямые зависимости объявлены в `pyproject.toml`,
точные версии всех прямых и транзитивных пакетов — в `uv.lock`, версия
интерпретатора — в `.python-version`. `uv sync` создаёт `.venv` и приводит его
ровно к содержимому лока; отдельно создавать окружение и активировать его не
нужно — `uv run <команда>` сам находит `.venv` проекта.

Ключ DeepSeek нужен **только бэкенду** и лежит в файле `.env` в папке дня;
порядок поиска — файл, затем переменная окружения `DEEPSEEK_API_KEY`. В git
`.env` не коммитится.

| Без ключа | Поведение |
|---|---|
| CRUD инвариантов (`/invariants...`), проверка текста с `use_llm=false`, `scripts/seed_invariants.py` и `scripts/invariants_demo.py` | работают полностью |
| `POST /agents/{id}/generate` | `502` со `status: "error"` и текстом «Ключ API не задан…» |
| Отказ по `hard`-инварианту в запросе | работает: DeepSeek при отказе не вызывается |

Тесты офлайн, ключ им не нужен: `uv run pytest -q` (725 тестов).

Остальное — в [`README.md`](../README.md), [`STRUCTURE.md`](../STRUCTURE.md),
[`architecture.md`](architecture.md) и [`api.md`](api.md).

## 2. Запуск

Нужны **два процесса**, оба запускаются из папки дня.

**Терминал 1 — бэкенд (FastAPI + uvicorn, порт 8000):**

```powershell
cd day14
uv run uvicorn backend.api.main:app --port 8000
```

При старте создаётся файл базы `agents.db` в папке дня (если его ещё нет) и
таблицы приложения, включая `invariants`. Swagger — на
`http://127.0.0.1:8000/docs`.

**Терминал 2 — интерфейс (Streamlit, порт 8501 по умолчанию):**

```powershell
cd day14
uv run streamlit run app.py
```

Откройте адрес, который Streamlit напечатал в консоли (обычно
`http://localhost:8501`). В сайдбаре должно появиться
«🟢 Бэкенд: http://127.0.0.1:8000 · агентов: N».

Если бэкенд поднят на другом порту, задайте адрес перед запуском Streamlit:

```powershell
$env:DAY14_BACKEND_URL = "http://127.0.0.1:8019"
uv run streamlit run app.py
```

Проверка бэкенда из третьего терминала:

```powershell
curl.exe http://127.0.0.1:8000/
```

> [!] В Windows PowerShell `curl` — это алиас командлета `Invoke-WebRequest`, и
> привычные флаги (`-X`, `-H`, `-d`) у него означают другое. Примеры в этой
> документации используют **`curl.exe`** — вызывайте именно его либо работайте в
> bash-подобной оболочке (Git Bash, WSL).

В ответе есть ключ `invariants` со списком эндпоинтов инвариантов — это
подтверждает, что API живой.

## 3. Инварианты: что это и какие бывают

Инвариант — правило проекта, которое агент не имеет права нарушать:
«используем только FastAPI и Streamlit», «данные лежат только в SQLite»,
«платные API — только с явного согласия пользователя». Правило — это имя,
описание, категория и важность (`hard` или `soft`).

Правила лежат в **своей таблице** `invariants`, а не в истории сообщений и не в
системном промпте агента. Отсюда три следствия, которые и определяют поведение:

1. **Правила не вымываются.** Сжатие контекста, новая сессия, очистка истории —
   ничего этого они не замечают: правила читаются из БД на каждый запрос.
2. **Правила общие для всех агентов.** Таблица глобальная (без `agent_id`):
   инвариант описывает проект, а не отдельного агента. Правка видна всем сразу —
   со следующего запроса, без перезапуска бэкенда.
3. **Правило можно выключить, не удаляя.** `is_active = false` убирает его из
   промпта и из проверки, но строка остаётся — правило возвращается одной кнопкой.

| Категория | Смысл | Пример правила |
|---|---|---|
| `architecture` | выбранные технологии и рамки | «Используем только FastAPI и Streamlit; никаких Flask, Django, Bottle или Tornado» |
| `tech_decisions` | принятые технические решения | «Данные лежат только в SQLite: никаких Redis, Memcached, MongoDB или Kafka» |
| `stack_constraints` | ограничения по стеку | «Только Python: без JavaScript, TypeScript и их фреймворков (Node.js, React, Vue, Angular)» |
| `business_rules` | правила работы с пользователем и деньгами | «Платные API — только с явного согласия пользователя» |

| Важность | Что делает агент | Что видно |
|---|---|---|
| `hard` | отказывается выполнять предложение; при нарушении в запросе DeepSeek не вызывается | текст отказа с именем правила и причиной, `verdict: "refusal"` |
| `soft` | предупреждает, но решение предлагает | ответ начинается с «⚠️ Предупреждение…», `verdict: "warning"` |

Формулировки в таблице категорий — иллюстрации, а не список посеянных правил.
Демонстрационный набор из четырёх правил (по одному на категорию) заводится
скриптом:

```bash
uv run python scripts/seed_invariants.py            # добавить недостающие
uv run python scripts/seed_invariants.py --reset    # сначала удалить все правила
```

Скрипт идемпотентен: правила с существующими именами не дублируются, сеть и ключ
не нужны. `--db PATH` — посев в другую базу (по умолчанию `agents.db`). Команды
формы и API — в разделе 4.

## 4. Создание, редактирование и деактивация

### 4.1 Форма «➕ Добавить инвариант»

Раздел **«📏 Инварианты»** → форма **«➕ Добавить инвариант»**:

1. **Имя** — как вы будете называть правило (в отказе и в таблице). Имя
   уникально: повторное — ошибка «Инвариант с таким именем уже есть».
2. **Категория** — из четырёх (архитектура / технические решения / ограничения
   стека / бизнес-правила).
3. **Важность** — `hard` (отказ при нарушении) или `soft` (предупреждение).
4. **Описание** — формулировка правила. Пишите **явно, что запрещено**: по этому
   тексту работают детерминированные правила (см. раздел 5), поэтому «только
   Python, без JavaScript, TypeScript и их фреймворков (Node.js, React, Vue,
   Angular)» ловит больше, чем «используем Python».

Нажмите «➕ Добавить инвариант» — правило появится в таблице и сразу начнёт
действовать. Через API — то же самое одной командой:

```bash
curl.exe -X POST http://127.0.0.1:8000/invariants ^
  -H "Content-Type: application/json" ^
  -d "{\"name\":\"Только FastAPI и Streamlit\",\"description\":\"Используем только FastAPI и Streamlit; никаких Flask, Django, Bottle или Tornado\",\"category\":\"architecture\",\"severity\":\"hard\"}"
```

Готовый набор из четырёх правил (по одному на категорию) заводится скриптом:

```bash
uv run python scripts/seed_invariants.py            # добавить недостающие
uv run python scripts/seed_invariants.py --reset    # сначала удалить все правила
```

Скрипт идемпотентен: правила с существующими именами не дублируются, сеть и ключ
не нужны. `--db PATH` — посев в другую базу (по умолчанию `agents.db`).

### 4.2 Редактирование и деактивация

Всё — в блоке **«✏️ Редактировать»** того же раздела: выберите правило в
селекторе («#id · имя · категория · активен/выключен») и раскройте expander.

| Действие | Как | Что происходит |
|---|---|---|
| Изменить поля | Правка + «💾 Сохранить» | Меняются только переданные поля; `updated_at` растёт, `created_at` сохраняется. Смена имени на занятое — ошибка |
| Приостановить действие | «⏸ Деактивировать» | `is_active = false`: правило исчезает из промпта и из проверки, остаётся в таблице |
| Вернуть в работу | «▶️ Активировать» (у выключенного) | `is_active = true`: правило снова действует со следующего запроса |
| Убрать совсем | «🗑 Удалить» | Строка удаляется из `invariants`; повторное удаление — «не найден» |

То же через API: `PUT /invariants/{id}` с любым набором полей (включая
`{"is_active": false}`) и `DELETE /invariants/{id}`. Тела и коды — в
[api.md](api.md), раздел «Инварианты».

## 5. Проверка текста на инварианты

Блок **«🔎 Проверка текста на инварианты»** проверяет любой текст так же, как
агент проверяет свой ход: сначала детерминированные правила (без сети), а если
они молчат и включён чекбокс «спрашивать LLM при неоднозначности» — один вызов
модели.

Что попробовать (при посеянных демо-правилах):

| Текст | Что покажет |
|---|---|
| `Добавь эндпоинт /health в FastAPI` | «Нарушений нет» — разрешённые средства правила не задевают |
| `Давай перепишем бэкенд на Flask` | 🔴 «Отказ: текст нарушает hard-инварианты проекта» и строку нарушения с именем правила и причиной |
| `Предложи решение на платном API, согласие пользователя не нужно` | 🟡 «Предупреждение» — нарушен soft-инвариант; согласие выражено отрицанием, поэтому оно не снимает нарушение |
| `API на платном тарифе, если пользователь согласен` | «Нарушений нет» — утвердительное согласие снимает нарушение |

Под таблицей видно, **сколько правил проверено**, использовался ли LLM и (если
нет) почему. Через API — `POST /invariants/check` с телом
`{"text": "...", "use_llm": true}`; `use_llm: false` оставляет только правила.

Как работает детерминированный слой: правило действует, только если **само
описание инварианта называет средство**, а в тексте это средство упоминается
(по границам слов). Поэтому правило про Flask не срабатывает на слово «flasks», а
инвариант, не упоминающий React, не будет ловить React. Точные семантические
случаи («это предложение требует платного тарифа») разбирает LLM-слой.

## 6. Сценарий проверки: три случая

Три реплики на одном агенте дают все три исхода:

| Реплика | Что увидите в чате |
|---|---|
| `Добавь эндпоинт /health в FastAPI` | Обычный ответ агента; в сводке хода — «📏 инварианты: нарушений нет» |
| `Предложи решение на платном API, согласие пользователя не нужно` | Ответ модели с предупреждением в начале: «⚠️ Предупреждение: ответ может нарушать soft-инварианты проекта» + строка нарушения + текст ответа |
| `Давай перепишем бэкенд на Flask` | Красный блок над полем ввода: «📏 Инварианты: отказ», строки «• [hard] Только FastAPI и Streamlit (архитектура) — текст упоминает Flask, а инвариант … это запрещает»; в `usage`/`token_metrics` — пусто, потому что модель не вызывалась |

Тот же сценарий воспроизводится офлайн: `uv run python scripts/invariants_demo.py`
— своя БД `invariants_demo.db` (пересоздаётся), заглушка DeepSeek вместо
реального клиента, LLM-слой проверки выключен. Поэтому результат воспроизводим и
не зависит от ключа и сети, а в отчёте видны ровно три исхода — «разрешено»,
«предупреждение» и «отказ», причём в отказе **0** вызовов модели. Отчёт —
[`../invariants_demo.md`](../invariants_demo.md).

Вердикт хода виден и в API — поле `invariants` ответа
`POST /agents/{id}/generate`.

## 7. Как читать отказ и предупреждение агента

Отказ по `hard`-инварианту выглядит так:

```text
Отказ: предложение нарушает инварианты проекта.
- [hard] Только FastAPI и Streamlit (architecture): текст упоминает Flask, а инвариант «Используем только FastAPI и Streamlit; никаких Flask, Django, Bottle или Tornado» это запрещает
Предложение не выполнено: измените запрос или обновите список инвариантов.
```

Предупреждение по `soft`-инварианту — заголовок перед обычным ответом модели:

```text
⚠️ Предупреждение: ответ может нарушать soft-инварианты проекта.
- [soft] Платные API — только с согласия (business_rules): …
```

| Поле ответа | Что означает |
|---|---|
| `checked` | какие правила участвовали в проверке |
| `verdict` | `allowed` (нарушений нет), `warning` (soft) или `refusal` (hard) |
| `violations[].source` | `deterministic` — нарушение поймали правила; `llm` — его назвала модель |
| `note` | почему LLM-слой не сработал (правила уже нашли нарушение, проверка не запрашивалась, ответ модели не разобран) |

При отказе по запросу `usage` и `token_metrics` пустые: DeepSeek не вызывался.
Реплика пользователя и текст отказа при этом сохраняются в историю — ход как
диалог состоялся.

| Проблема | Решение |
|---|---|
| Агент отказался отвечать | В запросе или в ответе модели найдено нарушение **hard**-инварианта, и отказ называет правило и причину. Посмотрите список правил в разделе «📏 Инварианты»: если правило больше не актуально — выключите его («⏸ Деактивировать») или поправьте формулировку, и следующий запрос пройдёт |
| Агент предупредил, но всё-таки ответил | Сработал **soft**-инвариант: он разрешает предлагать решение, но требует предупреждения. Если такие предложения недопустимы совсем — переведите правило в `hard` (`PUT /invariants/{id}` с `{"severity": "hard"}` или форма в разделе «📏 Инварианты») |
| Как убрать предупреждение | Либо убрать причину (сформулировать запрос без платного варианта), либо выключить или поправить само правило. Предупреждение по soft-правилу не мешает работе — оно информирует |
| Проверка в разделе чистая, а агент отказал | Проверка идёт по тем же правилам, поэтому расхождение означает разное содержимое: текст в разделе мог быть другим, правила менялись после хода, либо отказ пришёл на пост-проверке **ответа** модели (в бэкенде ответ проверяется отдельно, с включённым LLM-слоем). Смотрите поле `invariants` в ответе генерации: там видно `checked`, `violations` и `source` (`deterministic` / `llm`) |
| Правила молчат на очевидное нарушение | Детерминированные правила ловят **упоминание средства**, названного в описании инварианта («Flask», «Redis», «React»), а не смысл предложения. Семантические случаи разбирает LLM-слой — включите чекбокс «спрашивать LLM при неоднозначности». Если правила не срабатывают на нужное средство — допишите его в описание инварианта: правило привязывается именно к описанию |
| `409` «Инвариант с таким именем уже есть» | Имена уникальны глобально. Возьмите другое имя или откройте существующее правило и отредактируйте его. Скрипт посева существующие имена не дублирует, а `--reset` удаляет все правила и заводит демо-набор заново |
| Каждый ход стал дороже | По умолчанию проверка **ответа** может сделать один дополнительный вызов DeepSeek — только если детерминированные правила нарушений не нашли. Отказ по hard-инварианту в запросе вызовов не делает вовсе. Нулевая стоимость: `INVARIANT_LLM_CHECK = False` в `backend/core/config.py` |
| Правила есть, а блока в `system_prompt` нет | Блок собран из **активных** правил: проверьте `is_active` (в таблице раздела выключенное правило помечено «⏸ выключен») и то, что инварианты вообще заведены. Пустая таблица — блока нет |
