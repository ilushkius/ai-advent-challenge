# День 9 — установка и использование

Практическое руководство по запуску и работе с приложением дня 9
(«Управление контекстом: сжатие истории»). Детали устройства — в
[architecture.md](architecture.md), контракты HTTP — в [api.md](api.md).

День 9 развивает день 8: агент по-прежнему помнит **всю** историю в SQLite, но в
запрос к DeepSeek отправляет не её целиком, а **конспект старых реплик плюс
последние N сообщений «как есть»**. Интерфейс показывает, сколько токенов это
экономит и во сколько обходится сам конспект.

---

## 1. Установка зависимостей

Нужен **Python 3.14+**. Все команды выполняются из папки `day9` в PowerShell.

```powershell
cd day9
python -m venv .venv
.venv/Scripts/python -m pip install --upgrade pip
.venv/Scripts/python -m pip install -r requirements.txt
```

Проверка, что все зависимости импортируются (одна команда, ничего не запускает):

```powershell
.venv/Scripts/python -c "import fastapi, uvicorn, streamlit, openai, requests, sqlalchemy, tiktoken, httpx, pytest, pandas; print('ok')"
```

Ожидаемый вывод — `ok`. Если какой-то пакет не найден, повторите
`pip install -r requirements.txt` (убедитесь, что активирован именно `.venv`).

### Состав `requirements.txt`

| Пакет | Зачем он дню 9 |
|---|---|
| `fastapi>=0.111.0` | HTTP-API бэкенда, Swagger, валидация Pydantic |
| `uvicorn[standard]>=0.30.0` | ASGI-сервер, на котором живёт FastAPI |
| `streamlit>=1.30.0` | веб-интерфейс чата, панели сжатия и токенов |

Тесты (по желанию, из папки `day9`): `.venv/Scripts/python -m pytest -q`.

## 2. Переменные окружения: ключ DeepSeek

Ключ DeepSeek нужен **только бэкенду**. Фронтенд ключ не читает — он общается с
бэкендом по HTTP, поэтому вводить ключ в интерфейсе нигде не нужно.

Порядок поиска ключа:

1. файл `day9/.env` (строка `DEEPSEEK_API_KEY=...`);
2. переменная окружения `DEEPSEEK_API_KEY`.

Создайте `.env` из шаблона и впишите свой ключ:

```powershell
copy .env.example .env
```

```dotenv
# day9/.env
DEEPSEEK_API_KEY=sk-ваш-ключ
```

Файл `day9/.env` не коммитится в git. Если ключа нет:

| Без ключа | Поведение |
|---|---|
| Создание/список/правка/удаление агентов, история, конспекты, метрики | работают полностью |
| `POST /agents/{id}/generate` (реальный ответ модели) | `502` со `status: "error"` и понятным текстом вроде «Ключ API не задан…» |
| `POST /agents/{id}/compare` без `call_api` | работает: считаются только токены |

Дополнительно фронтенд понимает переменную `DAY9_BACKEND_URL` — адрес бэкенда,
по умолчанию `http://127.0.0.1:8000`. Менять её нужно, если бэкенд поднят на
другом порту:

```powershell
$env:DAY9_BACKEND_URL = "http://127.0.0.1:8019"
.venv/Scripts/python -m streamlit run app.py
```

## 3. Запуск

Нужны **два процесса**, оба запускаются из папки `day9`.

**Терминал 1 — бэкенд (FastAPI + uvicorn, порт 8000):**

```powershell
cd day9
.venv/Scripts/python -m uvicorn backend.main:app --port 8000
```

При старте бэкенд создаёт файл базы `day9/agents.db` (если его ещё нет) и таблицы
`agents`, `messages`, `summaries`, `token_usage`. Диалог, конспекты и метрики
переживают перезапуск. Swagger — на `http://127.0.0.1:8000/docs`.

**Терминал 2 — интерфейс (Streamlit, порт 8501 по умолчанию):**

```powershell
cd day9
.venv/Scripts/python -m streamlit run app.py
```

Откройте адрес, который Streamlit напечатал в консоли (обычно
`http://localhost:8501`). В сайдбаре должно появиться
«🟢 Бэкенд: http://127.0.0.1:8000 · агентов: N».

Проверка бэкенда из третьего терминала:

```powershell
curl.exe http://127.0.0.1:8000/
```

> [!] В Windows PowerShell `curl` — это алиас командлета `Invoke-WebRequest`, и
> привычные флаги (`-X`, `-H`, `-d`) у него означают другое. Примеры в этой
> документации используют **`curl.exe`** — вызывайте именно его либо работайте в
> bash-подобной оболочке (Git Bash, WSL).

`GET /` вернёт список эндпоинтов — это подтверждает, что API живой.

## 4. Сценарии использования

### 4.1 Создать агента

Всё создание живёт в сайдбаре, в блоке **«➕ Новый агент»** (форма
`create_agent_form`, очищается после отправки).

| Элемент формы | Что задаёт | Значение по умолчанию |
|---|---|---|
| «Имя агента» | человекочитаемое имя (например, «Конспектёр») | — (обязательно) |
| «Модель» | `deepseek-chat` или `deepseek-reasoner` | `deepseek-chat` |
| «Температура» | 0.0 … 2.0, шаг 0.1 | 0.7 |
| «Системный промпт (роль)» | роль агента; пусто — системного сообщения нет | пусто |
| «max_tokens» | 1 … 8192 — лимит длины ответа | 2048 |
| «Сжимать историю в конспект» | чекбокс: включён ли режим сжатия | включён |
| «Последних реплик «как есть»» | 2 … 20 — сколько последних сообщений всегда уходит дословно | 6 |
| «Сжимать каждые N новых реплик» | 2 … 40 — порог, после которого старые реплики уходят в конспект | 10 |

Что означают два слайдера:

* **«Последних реплик «как есть»»** — «свежий хвост» диалога. Эти сообщения
  уходят в запрос дословно, конспект их не заменяет: агенту важнее точный
  недавний контекст.
* **«Сжимать каждые N новых реплик»** — порог сжатия. Как только непокрытых
  конспектом реплик стало не меньше N, самая старая их часть заменяется
  конспектом (в запрос идёт конспект + хвост из предыдущего слайдера).

**Разумные значения по умолчанию — 6 и 10**, они подходят большинству
экспериментов. Уменьшайте `keep_last` и `summarize_every`, если сообщения
длинные и хочется увидеть экономию быстрее; увеличивайте — если реплики короткие.

Чекбокс сжатия можно позже переключить у живого агента (см. п. 4.3): между
перезапусками сохраняется последнее значение.

Нажмите **«Создать агента»**. Новый агент сразу становится активным, а в сайдбаре
появится строка вида
`Конспектёр · deepseek-chat · 0 сообщений · 🗜 сжатие`.

### 4.2 Вести чат

Поле **«Сообщение агенту»** и кнопка **«🚀 Отправить»** — внизу страницы. Пока
поле пустое, кнопка неактивна. Отправка идёт через
`POST /agents/{agent_id}/generate`, и в зависимости от режима в запрос уходит
разное:

| Режим | Что уходит в DeepSeek |
|---|---|
| Сжатие включено | system-сообщение (`system_prompt` + текст конспекта прошлой части диалога) → последние `keep_last` **непокрытых** конспектом реплик → новое сообщение пользователя |
| Сжатие выключено | system-сообщение (`system_prompt`, если задан) → **вся** история → новое сообщение пользователя |

Важно: конспект вкладывается в **существующее** системное сообщение, а не
добавляется вторым. Если нет ни конспекта, ни `system_prompt`, системного
сообщения в запросе нет вовсе.

Полная история при сжатии никуда не пропадает: все реплики лежат в таблице
`messages`, конспект лишь заменяет старую часть **в самом запросе**. В диалоге это
видно по жёлтому маркеру (п. 4.6) на границе «конспект / свежий хвост».

После ответа появляется одна сводка: время, токены (`вход · выход · всего`),
стоимость, `finish_reason` и — если сжатие сработало — экономия вида
«🗜 конспект: сэкономлено N токенов (M%)». Предупреждения (`context.warning`,
ошибка сжатия) добавляются в ту же сводку.

### 4.3 Панель «🗜 Сжатие контекста»

Панель стоит над панелью токенов. Сверху — подпись с состоянием процесса словами
(например, «📥 накопление реплик», «⏳ пора сжимать», «⚠️ ошибка сжатия (повтор на
следующем ходу)»), режимом и текущими `keep_last` / `summarize_every`.

Четыре метрики:

| Метрика | Смысл |
|---|---|
| «Конспектов» | сколько записей в таблице `summaries` (append-only, текущий — последняя) |
| «Реплик в конспекте» | сколько реплик заменено конспектом в запросах |
| «Сэкономлено» | разница между полным контекстом и отправленным (оценка tiktoken) |
| «Чистая экономия» | сэкономленные токены запросов **минус** токены, потраченные на вызовы суммаризации |

Ниже — полоса прогресса покрытия и подпись «Покрыто конспектом: X из Y реплик ·
до следующего сжатия осталось Z непокрытых · стоимость конспектов $…».

Под метриками — **expander «📝 Текущий конспект (N реплик, X токенов)»**: внутри
текст конспекта, а в подписи — дата создания, размер исходного текста и
коэффициент сжатия (`сжатие ×…`). Если конспекта ещё нет, панель пишет, что
истории не хватает до порога.

Кнопка **«🗜 Сжать сейчас»** — принудительное сжатие: всё, кроме последних N
реплик, уходит в конспект (через `POST /agents/{id}/summarize` с `force: true`).
Полезно для демонстрации, когда порог ещё не достигнут. Если сжимать нечего,
всплывёт сообщение «Сжимать пока нечего: …» — это не ошибка.

Кнопка-переключатель **«⏸ Отключить сжатие» / «▶️ Включить сжатие»** меняет режим
живого агента запросом `PATCH /agents/{id}` с полем `summary_enabled`. Отключение
возвращает поведение дня 8 — в запрос снова идёт вся история; **сохранённые
конспекты при этом не удаляются**, они просто перестают использоваться.

### 4.4 Панель «📊 Токены диалога»

Данные берутся из `GET /agents/{id}/usage` и `GET /agents/{id}/usage/graph`.

Четыре метрики: «Использовано за диалог» (токенов), «Запросов», «Стоимость»
(`$…`), «Сэкономлено сжатием» (токенов).

Ниже — индикатор лимита: полоса заполнения и подпись «Контекст диалога: занято
**X** из **Y** токенов · до лимита осталось **Z**». Если остаток меньше 10 % от
лимита, появляется предупреждение, что контекст почти заполнен.

Далее — график **«📈 Рост токенов и накопленная экономия»** с тремя линиями:

* накопленные `total_tokens` за диалог;
* накопленная экономия (`saved_tokens`);
* `sent_context_tokens` — отправлено в последнем запросе.

В раскрывающемся блоке **«Таблица записей token_usage»** — все записи метрик с
колонками «время», «запрос», «ответ», «всего», «без сжатия», «отправлено»,
«сэкономлено», «режим» (`🗜 сжатие` / `📜 полная`), «стоимость $», «накоплено»,
«накопл. экономия». Пока запросов не было, панель пишет, что график и таблица
появятся после первого запроса.

### 4.5 Сравнение режимов «⚖️ Сравнить режимы»

Блок **«⚖️ Сравнить режимы: без сжатия и со сжатием»** — раскрывающийся
expander. Он отвечает на вопрос «сколько токенов даёт сжатие на **одном и том же**
промпте, не трогая историю».

1. Введите промпт в поле **«Промпт для сравнения»**.
2. При желании поставьте галочку **«Вызвать DeepSeek дважды (сравнить и ответы, и
   токены)»**. Без галочки считается **только токены** — это работает даже без
   ключа API.
3. Нажмите **«⚖️ Сравнить»** (`POST /agents/{id}/compare`).

Результат разложен на две колонки:

| 📜 Без сжатия | 🗜 Со сжатием |
|---|---|
| вся история; метрика «Токенов контекста» | конспект + последние реплики; метрика «Токенов контекста» со снятой дельтой |
| `usage` (вход/выход) и стоимость — только при вызове API | `usage` и стоимость — только при вызове API |

Внизу — итог: «Экономия контекста: **N** токенов (**M%**) · конспект:
использован/не использован · покрыто реплик: K». Так сравнение читается в двух
плоскостях: **токены контекста** (видно всегда) и **качество ответов** (видно,
если вызвать модель дважды).

**История диалога при сравнении не меняется**: ни реплики, ни конспекты, ни
метрики не записываются. Это безопасный способ «прикинуть» выгоду.

### 4.6 Сценарий демонстрации для видео

Единственный сценарий (в README дня — только ссылка на этот пункт).

**Подготовка.** Запустите оба процесса (п. 3), ключ DeepSeek в `day9/.env` задан.

1. Создать агента: имя «Конспектёр», модель `deepseek-chat`, чекбокс «Сжимать
   историю в конспект» включён, слайдеры **6** и **10**. Показать строку агента в
   сайдбаре и что панель сжатия говорит «накопить нечего».
2. Провести диалог примерно на **20 реплик** (10 пар «вопрос → ответ») на одной
   теме, например про лимиты контекста. На каждом ходу показывать сводку с
   экономией и как заполняется «Контекст диалога». Примерно на 8–10-й паре
   объяснить, что на очередном ходу сработал порог и часть реплик ушла в конспект.
3. Показать жёлтый маркер **«🗜 выше N реплик заменены конспектом»** в истории —
   это и есть граница: выше неё реплики в запрос не идут.
4. Открыть панель «🗜 Сжатие контекста»: метрики «Конспектов», «Реплик в
   конспекте», «Сэкономлено» и «Чистая экономия»; раскрыть
   **«📝 Текущий конспект»** и прочитать, что осталось от старой части диалога;
   при желании нажать «🗜 Сжать сейчас».
5. Открыть панель «📊 Токены диалога»: показать график и таблицу, объяснить
   колонки «без сжатия» / «отправлено» / «сэкономлено» / «режим».
6. Открыть **«⚖️ Сравнить режимы»**, ввести один промпт и сначала сравнить
   **офлайн по токенам** (без галочки), а затем — с галочкой «Вызвать DeepSeek
   дважды», чтобы сравнить и ответы. Завершить показом таблиц в SQLite
   (команды из п. 4.8): `agents`, `messages`, `summaries`, `token_usage`.

Опционально: нажать «⏸ Отключить сжатие» (PATCH) и повторить один ход — в запрос
уйдёт вся история, экономия исчезнет; затем «▶️ Включить сжатие» обратно.

### 4.7 Очистка истории и удаление агента

**«🧹 Очистить историю»** (рядом с кнопкой отправки) вызывает
`DELETE /agents/{id}/history` и удаляет:

* все реплики из `messages`;
* все конспекты из `summaries`;
* все метрики из `token_usage`.

**Конфигурация агента не меняется**: имя, модель, температура, `system_prompt`,
`max_tokens` и настройки сжатия остаются. После очистки диалог начинается с нуля —
удобно повторять эксперимент с теми же параметрами.

**«🗑 Удалить агента»** (в карточке агента) вызывает `DELETE /agents/{id}` и
удаляет **и агента, и всё связанное**: реплики, конспекты, метрики (в схеме это
каскад). Действие необратимо.

### 4.8 Просмотр SQLite

База — обычный файл `day9/agents.db`, смотреть можно без установки чего-либо
лишнего. Примеры выполняются из папки `day9`.

Агенты (конфиг и настройки сжатия):

```powershell
.venv/Scripts/python -c "import sqlite3; print(sqlite3.connect('agents.db').execute('select agent_id, name, model, summary_enabled, keep_last_messages, summarize_every from agents').fetchall())"
```

Реплики (полная история; при сжатии не удаляются):

```powershell
.venv/Scripts/python -c "import sqlite3; print(sqlite3.connect('agents.db').execute('select id, agent_id, role, substr(content,1,60), timestamp from messages order by id').fetchall())"
```

Конспекты (append-only: текущий — последняя строка по `id`):

```powershell
.venv/Scripts/python -c "import sqlite3; print(sqlite3.connect('agents.db').execute('select id, agent_id, covered_from_message_id, covered_to_message_id, covered_messages, source_tokens, summary_tokens, cost from summaries order by id').fetchall())"
```

Метрики, включая поля дня 9 (режим и экономию):

```powershell
.venv/Scripts/python -c "import sqlite3; print(sqlite3.connect('agents.db').execute('select id, agent_id, total_tokens, mode, full_context_tokens, sent_context_tokens, saved_tokens, summary_used from token_usage order by id').fetchall())"
```

Для интерактивной работы можно открыть файл любым SQLite-клиентом — формат
стандартный.

## 5. FAQ и возможные проблемы

| Проблема | Решение |
|---|---|
| «🔌 Бэкенд недоступен» в интерфейсе | Запустите бэкенд из папки `day9`: `.venv/Scripts/python -m uvicorn backend.main:app --port 8000`. Проверьте адрес: он должен совпадать с `DAY9_BACKEND_URL` (по умолчанию `http://127.0.0.1:8000`). |
| Порт 8000 (или 8501) занят | Запустите на другом порту: `uvicorn backend.main:app --port 8019` и, для фронтенда, задайте `$env:DAY9_BACKEND_URL="http://127.0.0.1:8019"`; Streamlit — `--server.port 8502`. |
| Генерация вернула `502` «Ключ API не задан» | Ключа нет ни в `day9/.env`, ни в переменной `DEEPSEEK_API_KEY`. Сделайте `copy .env.example .env` и впишите `DEEPSEEK_API_KEY=sk-...`, затем перезапустите бэкенд. CRUD при этом работает и без ключа. |
| Ошибка `429` (rate limit) от DeepSeek | Слишком много запросов подряд. Подождите и повторите; для демонстрации делайте паузы между ходами. Сравнение с галочкой «Вызвать DeepSeek дважды» тратит два запроса сразу. |
| Кнопка «Сжать сейчас» отвечает «Сжимать пока нечего» | Это нормально: непокрытых реплик меньше порога `summarize_every`, либо истории нет вовсе. Наберите диалог или уменьшите порог. Отчёт приходит с `created: false` и текстом причины. |
| «Чистая экономия» отрицательная | Конспект оказался дороже заменённых реплик — типично для коротких сообщений. Экономия контекста есть, но на сам конспект ушло больше токенов. Увеличьте `summarize_every` и/или `keep_last`, либо пишите более длинные реплики. |
| Оценки tiktoken не совпадают с `usage` API | Это ожидаемо: tiktoken (`cl100k_base`) — приблизительная оценка, у DeepSeek свой токенизатор. Для конкретного запроса/ответа верьте фактическим `usage` из API; на tiktoken построены расчёты контекста и экономии. |
| Контекст «упирается» в лимит слишком рано | Лимиты `8000` (`deepseek-chat`) и `32000` (`deepseek-reasoner`) — **демонстрационные**, они уже, чем реальный контекст модели. Меняются в `MODEL_TOKEN_LIMITS` в `backend/config.py`. |
| `deepseek-reasoner` ведёт себя странно с температурой | Эта модель может игнорировать `temperature` и добавляет скрытые рассуждения в `completion_tokens`, из-за чего ответ «дороже». Суммаризация всегда идёт на `deepseek-chat`, независимо от модели агента. |
| Где посмотреть состояние FSM сжатия | В панели «🗜 Сжатие контекста» — подпись «Состояние процесса: …» (`tracking`, `summary_pending`, `summarizing`, `error`). В БД оно не хранится: выводится из watermark, числа непокрытых реплик и порога. |
| `agents.db` попал в git | Не должен: файлы `*.db` игнорируются. Если он уже отслеживается, уберите из индекса (`git rm --cached day9/agents.db`) — файл останется на диске. |
| Как сбросить эксперимент | «🧹 Очистить историю» удаляет реплики, конспекты и метрики, сохраняя конфигурацию агента. Полный сброс — «🗑 Удалить агента» и создать заново; можно также остановить бэкенд и удалить `day9/agents.db` (таблицы создадутся заново). |
| Сравнение зависает дольше обычного | Сравнение с галочкой «Вызвать DeepSeek дважды» — это **два** запроса к модели; у фронтенда таймаут 90 с. Для быстрой проверки снимите галочку — посчитаются только токены. |
| `422` при создании/правке агента | Проверьте значения: `temperature` 0.0–2.0, `max_tokens` 1–8192, `keep_last_messages` 2–20, `summarize_every` 2–40. Такой ответ означает ошибку валидации тела запроса. |
| `404` на агента | Агент был удалён или `agent_id` указан неверно. Обновите список кнопкой «🔄 Обновить список» и выберите агента заново. |
