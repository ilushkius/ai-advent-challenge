# Проверка документации перед коммитом дня

Правило дня: **день не закрывается без раздела в `docs/usage.md`** об запуске новой
функциональности. Полный чек-лист живёт в `day21/AGENTS.md` («Обязательное завершение
дня»), эта процедура — быстрая проверка перед `git commit`.

## Чек-лист

1. `docs/usage.md` — есть раздел про новую функциональность: **команды** запуска,
   **шаги в UI** (какая вкладка, какая кнопка, что появится на экране), **скрипты с
   флагами** и где смотреть результат. Нет раздела — создать.
2. `README.md` — есть ссылка на новый функциональный блок и на отчёт дня. Нет — добавить.
3. `docs/architecture.md` — описана новая архитектура и поток данных (схема), а не
   только список файлов.
4. `docs/reports/<тема>.md` — создан, если задание требует сравнения или демонстрации;
   числа в нём сняты прогоном, а не выдуманы.
5. `CHANGELOG.md` (корень) — запись дня в формате соседних записей.

## Правило проверки

Перед коммитом задать вопрос: «Если человек впервые откроет проект через месяц,
поймёт ли он, как запустить то, что я только что сделал?» Если ответ «нет» —
дописать документацию и только потом коммитить.

## Как проверять (команды)

Из папки `day21/`:

```bash
grep -n "Локальный RAG\|НазваниеРаздела" docs/usage.md     # раздел есть?
grep -n "docs/usage.md\|docs/reports/" README.md            # ссылки в README есть?
grep -n "^## " docs/usage.md | tail -5                      # нумерация разделов не поехала
```

## Чего делать нельзя

- Коммитить код без раздела в `docs/usage.md`, «пообещав» дописать документацию после.
- Дублировать один и тот же текст в `README.md`, `docs/usage.md` и
  `docs/architecture.md`: README — «что это и как запустить», `usage.md` — пошаговая
  инструкция, `architecture.md` — как устроено.
- Копировать разделы прошлых дней: документация описывает только текущее состояние.
