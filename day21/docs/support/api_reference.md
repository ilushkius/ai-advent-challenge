# Справочник API продукта

Ключевые эндпоинты, которыми пользуются клиенты поддержки: авторизация, профиль,
подписка и платежи, ключи доступа и вебхуки. Для каждого эндпоинта указаны метод и
путь, параметры, коды ответов и пример вызова. Документ — часть корпуса RAG-индекса
ассистента поддержки (день 33): раздел одного эндпоинта становится отдельным
фрагментом контекста, поэтому примеры повторяют то, что видит клиент в терминале.

Базовый адрес боевого окружения — `https://api.example.com`, песочницы —
`https://api.test.example.com`. Все тела запросов и ответов — JSON в кодировке
UTF-8.

## POST /auth/token

Выпускает пару токенов по email и паролю. Токен доступа живёт час и передаётся в
заголовке `Authorization`, токен обновления живёт тридцать дней и меняется на новую
пару запросом `POST /auth/token` с полем `grant_type`.

Параметры (тело JSON):

- `email` — email пользователя, обязательное поле;
- `password` — пароль, обязательное поле;
- `grant_type` — `password` (по умолчанию) или `refresh_token`;
- `refresh_token` — обязательное поле при `grant_type=refresh_token`;
- `totp` — шестизначный код приложения-аутентификатора, если включена 2FA.

Коды ответов: `200` — пара токенов; `400` — негодное тело запроса; `401` —
неверный пароль или истёкший токен обновления; `403` — требуется код 2FA; `429` —
слишком много попыток входа с одного IP.

```bash
curl -X POST https://api.example.com/auth/token \
  -H 'Content-Type: application/json' \
  -d '{"email": "m.kuznetsova@example.com", "password": "secret", "grant_type": "password"}'
```

```json
{
  "access_token": "eyJhbGciOi...",
  "refresh_token": "rt_9f13c...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "user": {"id": "user_003", "name": "Мария Кузнецова", "plan": "pro"}
}
```

## GET /me

Возвращает профиль владельца токена или ключа API: идентификатор, имя, email,
тариф, даты регистрации и последней активности. Эндпоинт удобен как проверка
работоспособности ключа: он не требует параметров и отвечает мгновенно.

Параметры: нет.

Коды ответов: `200` — профиль; `401` — токен или ключ не принят; `403` — ключ
относится к другому окружению.

```bash
curl https://api.example.com/me -H 'Authorization: Bearer <ключ>'
```

```json
{
  "id": "user_003",
  "name": "Мария Кузнецова",
  "email": "m.kuznetsova@example.com",
  "plan": "pro",
  "registered_at": "2026-05-21",
  "last_seen": "2026-10-14"
}
```

## POST /billing/subscription

Меняет тариф подписки. Переход на более дорогой тариф списывает деньги сразу за
первый период, понижение вступает в силу с начала следующего периода. Повторный
вызов с тем же тарифом возвращает текущее состояние без списания.

Параметры (тело JSON):

- `plan` — `free`, `pro` или `enterprise`, обязательное поле;
- `period` — `month` или `year` (по умолчанию `month`);
- `organization_id` — организация, к которой применяется тариф; если не указана,
  берётся организация текущего пользователя.

Коды ответов: `200` — состояние подписки; `400` — неизвестный тариф или период;
`402` — платёж отклонён банком; `409` — уже идёт смена тарифа; `429` — слишком много
попыток оплаты подряд.

```bash
curl -X POST https://api.example.com/billing/subscription \
  -H 'Authorization: Bearer <токен>' -H 'Content-Type: application/json' \
  -d '{"plan": "pro", "period": "month", "organization_id": "org_0042"}'
```

```json
{
  "organization_id": "org_0042",
  "plan": "pro",
  "period": "month",
  "status": "active",
  "current_period_end": "2026-11-14T00:00:00Z",
  "limits": {"requests_per_second": 50, "requests_per_minute": 3000}
}
```

## GET /billing/invoices

Список платежей и закрывающих документов за период. Для юридических лиц параметр
`format=zip` отдаёт архив со всеми счетами и актами периода.

Параметры (query):

- `from` — начало периода в формате `YYYY-MM-DD`;
- `to` — конец периода в формате `YYYY-MM-DD`;
- `status` — `paid`, `refunded`, `pending`; по умолчанию все;
- `format` — `json` (по умолчанию) или `zip`;
- `limit` — размер страницы, до 100 записей.

Коды ответов: `200` — список платежей; `400` — негодный период или формат; `401` —
токен не принят; `404` — документы за период не сформированы.

```bash
curl 'https://api.example.com/billing/invoices?from=2026-09-01&to=2026-09-30&status=paid' \
  -H 'Authorization: Bearer <токен>'
```

```json
{
  "count": 2,
  "invoices": [
    {"id": "inv_2026_09_114", "amount": 199000, "currency": "RUB",
     "paid_at": "2026-09-27T21:14:00Z", "status": "paid"},
    {"id": "inv_2026_09_115", "amount": 199000, "currency": "RUB",
     "paid_at": "2026-09-27T21:16:00Z", "status": "refunded"}
  ]
}
```

## POST /api-keys

Создаёт ключ доступа. Значение ключа показывается один раз — в ответе на создание;
повторно его получить нельзя, можно только отозвать ключ и создать новый.

Параметры (тело JSON):

- `name` — человекочитаемое имя ключа, обязательное поле;
- `environment` — `test` или `live` (по умолчанию `test`);
- `scopes` — список разрешений: `read`, `write`, `billing`; по умолчанию `read`;
- `expires_at` — необязательная дата истечения в формате ISO-8601.

Коды ответов: `201` — ключ создан; `400` — негодное имя, окружение или разрешения;
`409` — ключ с таким именем уже есть; `429` — превышено число ключей на тариф.

```bash
curl -X POST https://api.example.com/api-keys \
  -H 'Authorization: Bearer <токен>' -H 'Content-Type: application/json' \
  -d '{"name": "dashboard", "environment": "live", "scopes": ["read"]}'
```

```json
{
  "id": "key_live_7f3c",
  "name": "dashboard",
  "environment": "live",
  "value": "sk_live_7f3c9b2a...",
  "scopes": ["read"],
  "created_at": "2026-10-01T12:00:00Z"
}
```

## GET /api-keys

Список ключей организации. Значения ключей не возвращаются: только префикс, имя,
окружение, разрешения и время последнего использования. Ключ можно отозвать
запросом `DELETE /api-keys/{id}`.

Параметры (query):

- `environment` — фильтр `test` или `live`;
- `active` — `true` или `false`: показывать только активные или только отозванные.

Коды ответов: `200` — список ключей; `401` — токен не принят; `403` — нет
разрешения `write`.

```bash
curl 'https://api.example.com/api-keys?environment=live&active=true' \
  -H 'Authorization: Bearer <токен>'
```

```json
{
  "count": 2,
  "keys": [
    {"id": "key_live_7f3c", "name": "dashboard", "environment": "live",
     "prefix": "sk_live_7f3c", "last_used_at": "2026-10-02T16:05:00Z", "active": true},
    {"id": "key_live_11ab", "name": "worker", "environment": "live",
     "prefix": "sk_live_11ab", "last_used_at": null, "active": false}
  ]
}
```

## POST /webhooks

Создаёт подписку на события. Продукт отправляет событие методом POST на указанный
адрес с заголовком `X-Signature` (HMAC-SHA256 тела запроса) и повторяет доставку
пять раз с растущими паузами, если приёмник не ответил кодом 2xx за пять секунд.

Параметры (тело JSON):

- `url` — адрес приёмника, обязательное поле, только `https`;
- `events` — список событий: `task.created`, `task.closed`, `payment.paid`,
  `user.invited`;
- `format` — `json` (по умолчанию), `slack` или `telegram` для готовых приёмников;
- `secret` — секрет подписи; если не передан, генерируется на сервере.

Коды ответов: `201` — подписка создана; `400` — негодный адрес, событие или формат;
`409` — адрес уже подписан на те же события; `422` — адрес не прошёл проверку
доступности.

```bash
curl -X POST https://api.example.com/webhooks \
  -H 'Authorization: Bearer <токен>' -H 'Content-Type: application/json' \
  -d '{"url": "https://hooks.slack.com/services/T000/B000/XXXX",
       "events": ["task.created", "task.closed"], "format": "slack"}'
```

```json
{
  "id": "wh_51d2",
  "url": "https://hooks.slack.com/services/T000/B000/XXXX",
  "events": ["task.created", "task.closed"],
  "format": "slack",
  "secret": "whsec_3c9f...",
  "created_at": "2026-10-03T09:30:00Z"
}
```

## Аутентификация и лимиты

Два способа авторизации: заголовок `Authorization: Bearer <токен доступа>` — для
действий от имени пользователя, и заголовок `Authorization: Bearer <ключ API>` —
для серверных интеграций. Ключи окружений `test` и `live` несовместимы: эндпоинт
боевого окружения с тестовым ключом отвечает `401`.

Лимиты частоты считаются на ключ или на пользователя и скользят по последней
секунде и последней минуте: у `free` — 10 запросов в секунду и 60 в минуту, у
`pro` — 50 и 3000, у `enterprise` — 200 и договорной минутный лимит. При
превышении приходит `429` с заголовком `Retry-After`; повтор без задержки
продлевает ограничение.

Идемпотентность: запросы создания платежей и подписок принимают заголовок
`Idempotency-Key`. Повторный запрос с тем же ключом в течение суток возвращает
первый результат и не создаёт вторую операцию — это штатный способ пережить
таймаут сети без двойного списания.

Коды ошибок общие для всех эндпоинтов: `400` — негодные данные запроса, `401` —
не принят токен или ключ, `403` — нет разрешения на операцию, `404` — объекта нет,
`409` — конфликт состояния, `422` — проверка доступности не пройдена, `429` —
превышен лимит частоты, `5xx` — сбой на стороне сервиса; тело ошибки всегда
содержит поля `error` и `message` с русским текстом причины.
