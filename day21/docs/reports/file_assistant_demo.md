```diff
+# ADR 0001. DeepSeek как основной провайдер LLM
+
+- **Статус:** Принято
+- **Дата:** 2024-01-01
+- **Контекст решения:** выбор основного провайдера для генерации и обработки текста
+
+## Контекст
+
+Проекту нужен LLM-провайдер для выполнения основных сценариев: генерация текста, извлечение структурированных данных, работа с длинными документами и вызов инструментов. Ключевые требования:
+
+- стабильное качество ответов на русском и английском языках;
+- поддержка длинного контекста и вызова инструментов (function calling);
+- предсказуемая стоимость и простое ценообразование;
+- возможность локального/самостоятельного развёртывания весов;
+- совместимость с OpenAI-подобным API для минимизации изменений в коде.
+
+## Рассмотренные варианты
+
+1. **DeepSeek** — сильные модели, конкурентная цена, OpenAI-совместимый API, открытые веса.
+2. **OpenAI** — эталонное качество и экосистема, но высокая стоимость и внешние ограничения доступа.
+3. **Anthropic Claude** — хорошее качество и длинный контекст, но выше стоимость и иной формат API.
+4. **Локальные открытые модели** — полный контроль и отсутствие внешних зависимостей, но требуют инфраструктуры и сопровождения.
+
+## Решение
+
+Использовать **DeepSeek** в качестве основного провайдера LLM. Провайдер подключается через OpenAI-совместимый интерфейс, что позволяет сохранить единый слой абстракции и при необходимости заменить провайдера без переписывания прикладной логики.
+
+Провайдер задаётся конфигурацией (переменные окружения), а не хардкодится в модулях. Остальные провайдеры остаются доступны как резервные и подключаются через тот же интерфейс.
+
+## Последствия
+
+**Положительные:**
+
+- Снижение стоимости инференса при сопоставимом качестве.
+- Единый OpenAI-совместимый клиент — меньше кода и проще тестирование.
+- Возможность перейти на открытые веса при росте нагрузки.
+
+**Отрицательные и риски:**
+
+- Зависимость от доступности внешнего API и его лимитов.
+- Требуется контроль качества при смене версии модели.
+- Нужен запасной провайдер на случай деградации или недоступности сервиса.
+
+## Меры снижения рисков
+
+- Абстракция провайдера и конфигурируемые модели.
+- Резервный провайдер, переключаемый настройкой.
+- Логирование запросов и метрик качества для регулярной проверки.
```
