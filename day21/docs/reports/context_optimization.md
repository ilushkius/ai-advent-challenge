Отчёт о комплексной оптимизации контекста дня 21: какие механизмы включены, что
подтверждено фактом, а что осталось оценкой. Замеры сняты на этом окружении
(`omp 18.4.2`, Windows, `deepseek-flash`) 2026-09-29.

## 3. Проверка (шаг 8)

Сессия из `day21/` (`omp -p --mode json`, pid 27840), 42 с, 8 запросов:

1. `cat app.py` → `Blocked: Use the read tool instead of cat/head/tail` — перехват
   сработал, файл в контекст не попал.
2. `glob **/*.py` → файлы **только** `day21` (212 в выдаче из-за лимита 200 на
   вызов, дальше — отдельные вызовы), ни одного файла `day1`–`day20`.
3. Агент процитировал и sticky-правила из `day21/.omp/RULES.md`, и правила из
   `day21/AGENTS.md` — значит оба файла действительно инжектированы в контекст.
4. `omp plugin doctor` → `plugin:@mxalbert/context-mode … ok`.

Логи: `~/.omp/logs/omp.2026-09-29.27840.log` (сессия),
`~/.local/state/billion-context/bili.log` (компрессор).

## 4. Что осталось оценкой, а не замером

* **Целевые 40–70 %.** Измерены покомпонентно: исключение архива (100 % обхода,
  4,1× по байтам исходников), перехват команд (−98 % на конкретном вызове), оба
  слоя сжатия активны. Полный сквозной A/B «3 сессии до / 3 после» требует
  2–3 будущих сессий: процедура — `omp stats --json` до и после, сравнение
  `timeSeries` и `byAgentType` (команды в § 5).
* **Вендорские обещания** (`context-mode` — «98 % на тяжёлых выгрузках»,
  `billion-context` — «≈5× меньше токенов») не воспроизводились на этой нагрузке:
  замерены только факты включения и пороги.
* **Отдельный лейн `bili omp`** (запуск omp через прокси с cert-MITM) для
  `api.deepseek.com` работает в режиме blind tunnel — без хоста в whitelist
  (`BILI_MITM_HOSTS`) прокси релеит TLS нерасшифрованным и не сжимает. Рабочий
  путь — расширение в `~/.omp/agent/config.yml` (лейн `/bili/` без MITM): он
  перехватывает запросы, как показано в § 2.4.
* **`context-mode` без smol-модели**: в логе предупреждение
  `Skill description compression failed … No smol or tiny model available` —
  описания его скиллов не сжались. На работу песочницы и FTS5 не влияет.
* **График расхода в браузере** не смотрелся (Chromium не ставился); числа взяты
  из `omp stats --json`.

## 5. Как воспроизвести

```bash
# база и текущее состояние расхода (токены, кэш, стоимость, по дням и агентам)
omp stats --json > before.json      # до серии сессий
omp stats --json > after.json       # после 2-3 сессий

# проверка зоны видимости
cd day21 && omp -p "через glob **/*.py перечисли верхнеуровневые папки с .py"
# ожидается: только папки day21

# проверка перехвата
cd day21 && omp -p "выполни bash-команду cat app.py"
# ожидается: Blocked: Use the `read` tool instead of cat/head/tail

# состояние механизмов
omp config get bashInterceptor.enabled      # true
omp plugin list                             # context-mode, better-compact
bili plugin list omp                        # omp installed

# санитарная проверка скилла: исходники не вырезаны игнором
git ls-files --others --ignored --exclude-standard | grep -E '\.py$' \
  | grep -vE '(\.venv/|venv/|__pycache__/|site-packages/)'
# ожидается: только day21/documents/*.py (производные копии, они в игноре по проекту)
```

## 6. Правила, закреплённые за днём

* `day21/.omp/RULES.md` — sticky (omp делает sticky только native-локации:
  `~/.omp/agent/RULES.md` и `<ближайший непустой .omp/>/RULES.md`; файл в корне дня
  не загрузился бы — доки `omp://context-files.md`).
* `day21/AGENTS.md` — правила дня и workflow нового дня; подхватывается
  провайдером `agents-md` при запуске сессии из `day21/`.
* Корневой `.gitignore` — единственный из трёх «ignore»-файлов, который реально
  сужает зону обхода omp; `.clineignore` добавлен для Cline-совместимости.
