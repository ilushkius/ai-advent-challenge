## 7. Схема таблиц планировщика

### `scheduled_tasks`

Задачи планировщика: имя, инструмент, аргументы, расписание, состояние и метки запусков. Источник правды для восстановления после перезапуска

| колонка | тип | обязательна | значение по умолчанию |
|---|---|---|---|
| id | INTEGER | да | — |
| name | VARCHAR(100) | да | — |
| schedule_type | VARCHAR(16) | да | — |
| schedule_value | JSON | да | dict |
| tool_name | VARCHAR(64) | да | — |
| arguments | JSON | да | dict |
| status | VARCHAR(16) | да | active |
| last_run_at | DATETIME | нет | — |
| next_run_at | DATETIME | нет | — |
| created_at | DATETIME | да | utcnow |

### `task_runs`

Журнал запусков: «подготовка» при регистрации и каждый тик — результат, длительность, детали и текст ошибки

| колонка | тип | обязательна | значение по умолчанию |
|---|---|---|---|
| id | INTEGER | да | — |
| task_id | INTEGER | да | — |
| phase | VARCHAR(16) | да | — |
| status | VARCHAR(16) | да | — |
| started_at | DATETIME | да | — |
| finished_at | DATETIME | да | — |
| duration_ms | INTEGER | да | 0 |
| detail | JSON | нет | — |
| error | TEXT | нет | — |

### `reminders`

Напоминания: текст, момент выдачи и состояние (ждёт / выдано)

| колонка | тип | обязательна | значение по умолчанию |
|---|---|---|---|
| id | INTEGER | да | — |
| text | VARCHAR(500) | да | — |
| remind_at | DATETIME | да | — |
| status | VARCHAR(16) | да | scheduled |
| created_at | DATETIME | да | utcnow |
| task_id | INTEGER | нет | — |

### `notifications`

Очередь уведомлений: напоминание сработало, сводка готова, тик упал; `read_at` — прочитано ли

| колонка | тип | обязательна | значение по умолчанию |
|---|---|---|---|
| id | INTEGER | да | — |
| kind | VARCHAR(32) | да | — |
| text | VARCHAR(1000) | да | — |
| task_id | INTEGER | нет | — |
| payload | JSON | нет | — |
| created_at | DATETIME | да | utcnow |
| read_at | DATETIME | нет | — |

### `collected_data`

Накопленные записи сбора: имя сбора, адрес источника, ответ как есть и время

| колонка | тип | обязательна | значение по умолчанию |
|---|---|---|---|
| id | INTEGER | да | — |
| name | VARCHAR(100) | да | — |
| source_url | VARCHAR(500) | да | — |
| payload | JSON | нет | — |
| collected_at | DATETIME | да | utcnow |

### `periodic_summaries`

Регулярные сводки: текст, период, число записей и ключевые метрики

| колонка | тип | обязательна | значение по умолчанию |
|---|---|---|---|
| id | INTEGER | да | — |
| name | VARCHAR(100) | да | — |
| content | TEXT | да | — |
| period_start | DATETIME | да | — |
| period_end | DATETIME | да | — |
| total_records | INTEGER | да | 0 |
| key_metrics | JSON | да | dict |
| task_id | INTEGER | нет | — |
| created_at | DATETIME | да | utcnow |

Имя `periodic_summaries`, а не `summaries`: имя `summaries` в проекте уже занято конспектами сжатия истории (день 9), и переименовывать унаследованную таблицу нельзя.

## 9. Что осталось за рамками дня

* доставка уведомлений вне приложения (почта, мессенджер) — нет: очередь уведомлений живёт в БД и показывается в интерфейсе;
* cron-расписание доступно только переопределением расписания задачи (`schedule_type=cron`), из аргументов инструмента оно не выводится;
* сбор читает один адрес за задачу: несколько источников — это несколько задач `collect_data`;
* сводка агрегирует записи одного имени сбора (`name`) — сводка «по всем данным» задаётся другим именем;
* хранилище планировщика — SQLite в процессе бэкенда: несколько экземпляров приложения одновременно не поддерживаются (APScheduler живёт в одном).
