# День 21 — как пользоваться: индексация документов и сравнение стратегий

Инструкция дня 21. Что это, что нужно для запуска, что нажимать в интерфейсе, как
читать таблицу сравнения и метрики, как прогнать пять сценариев проверки и что
делать, если что-то не работает. Устройство (модули, таблицы, поток данных) — в
[`architecture.md`](architecture.md), контракт эндпоинтов — в [`api.md`](api.md).

## 1. Что делает день

День 21 надстраивает над приложением дня 20 (агент DeepSeek с памятью, профилем,
задачей, инвариантами, планировщиком, MCP-инструментами, пайплайном и оркестрацией)
**слой поиска по документам проекта**:

1. **собирает набор документов** из источников репозитория — 25 файлов
   (README дней 5–20, `docs/architecture.md` дней 9/13/20, четыре исходника,
   `AGENTS.md` и корневой `README.md`) ≈ 125 000 символов;
2. **режет документы на чанки двумя стратегиями** — `fixed` (окно по 512 токенов с
   перекрытием 50) и `structural` (секции: заголовки markdown, определения кода,
   абзацы);
3. **считает эмбеддинги** локальной моделью
   `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` и кладёт их в
   **FAISS**, а метаданные чанков — в SQLite;
4. **ищет по индексу**: запрос кодируется той же моделью, ближайшие чанки
   возвращаются с источником, секцией и оценкой близости;
5. **сравнивает стратегии** по метрикам: количество чанков, средний размер и
   разброс, покрытие документов, сохранение структуры, время индексации,
   precision@k и recall@k по пяти тестовым запросам;
6. **отдаёт фрагменты агенту**: если индекс построен, каждый ход агента ищет по нему
   и добавляет найденное в системный промпт (видно в поле `indexing` ответа).

Папку `documents/` и индексы готовить не нужно: и то, и другое создаёт код. В Git
они не попадают (производные данные).

## 2. Что нужно для запуска

| Что | Зачем | Обязательно |
|---|---|---|
| Python 3.14 и `uv` | зависимости дня (`pyproject.toml` + `uv.lock`) | да |
| ~1.5 ГБ диска | `torch` и веса модели эмбеддингов (~470 МБ) | да |
| `DEEPSEEK_API_KEY` в `.env` | чат, конспекты, проверка инвариантов, план оркестрации | только для чата; индексация работает без ключа |
| Интернет | первый прогон скачивает веса модели в `index/models/` | только один раз |

Установка (из папки дня — важен `cwd`: `.env` ищется здесь):

```bash
cd day21
uv sync                      # создаёт .venv по uv.lock
copy .env.example .env       # и впишите DEEPSEEK_API_KEY=sk-... (нужен только для чата)
```

Первое, что стоит сделать, — собрать документы и посмотреть, что попало в набор:

```bash
uv run python scripts/prepare_documents.py --list     # только показать манифест
uv run python scripts/prepare_documents.py --force    # пересобрать documents/ заново
```

Скрипт печатает число документов, суммарные символы, «страницы» (по 1800 символов)
и разбивку по видам (`readme`, `docs`, `code`, `guide`).

## 3. Запуск приложения

Два терминала из папки дня.

```bash
# терминал 1 — бэкенд (при старте читает индексы с диска и греет модель в фоне)
uv run uvicorn backend.api.main:app --port 8000

# терминал 2 — интерфейс
uv run streamlit run app.py        # http://localhost:8501
```

Разделов в интерфейсе девять; нужный — **«📦 Индексация»** (переключатель вверху
страницы). Соседние разделы — унаследованные от прошлых дней (чат и память, профиль,
состояние задачи, инварианты, MCP, планировщик, пайплайны, оркестрация) и для
индексации не требуются.

Проверить, что бэкенд жив и видит индексы, можно без интерфейса:

```bash
curl "http://127.0.0.1:8000/indexing/stats"
```

Пустой день отвечает нулями без ошибки — это нормально: индексов ещё нет.

## 4. Демо-индексация одной кнопкой

Раздел «📦 Индексация» → кнопка **«🚀 Запустить демо-индексацию»**.

Что происходит по шагам (этапы видны в прогресс-баре и подписи «Этап: …»):

| Этап | Что делает | Что видно |
|---|---|---|
| `loading` | собирает `documents/` из источников (если папки нет) и читает их | `документы 25/25` |
| `chunking` | режет документы обеими стратегиями | растут `чанков fixed/structural` |
| `embedding` | считает эмбеддинги батчами по 32 | растут `эмбеддингов X/Y` — это самый долгий этап |
| `indexing` | пишет строки в `document_chunks`, векторы в FAISS, файлы `index/*.index` | — |
| `searching` | выполняет пять тестовых запросов на каждой стратегии | — |
| `comparing` | считает метрики и таблицу сравнения | появляется таблица «Сравнение стратегий» |
| `completed` | готово | внизу — метрики, гистограммы, примеры чанков, запросы, история |

Сколько это занимает: с готовыми весами модели — минуты на CPU (в основном этап
`embedding`); первый прогон дольше, потому что скачивает веса (~470 МБ) в
`index/models/`. Прогон идёт в фоне (кнопка не «замораживает» страницу): можно
переключаться на другие разделы и вернуться — прогресс подтянется.

Тот же сценарий без интерфейса:

```bash
uv run python scripts/indexing_demo.py                    # настоящая модель, отчёт в docs/reports/indexing_demo.md
uv run python scripts/indexing_demo.py --stub-embedder    # офлайн: заглушка вместо модели
uv run python scripts/indexing_demo.py --skip-scenarios   # только отчёт по уже построенным индексам
```

Флаг `--stub-embedder` нужен, когда нет сети или не хочется ждать: прогон и отчёт
собираются, но **качество поиска тогда не показательно** — это печатается в выводе и
попадает в отчёт.

Под кнопкой есть раскрывающийся блок «Только одна стратегия и очистка индекса»:

* «Индексировать fixed» / «Индексировать structural» — прогон одной стратегией (без
  сравнения: сравнивать нечего);
* «🧹 Очистить обе стратегии» — убрать индексы, файлы и строки таблицы.

## 5. Как читать сравнение и гистограмму

**Таблица «Сравнение стратегий»** — главный результат дня. Строки:

| метрика | как читать |
|---|---|
| чанков | сколько фрагментов даёт стратегия. У `structural` обычно больше: секции короче окна |
| средний размер, токенов | у `fixed` близко к 512 (размер окна), у `structural` — сколько получилось |
| σ размера, токенов | разброс: у окна маленький, у секций большой — это и есть цена структуры |
| максимальный чанк, токенов | ни у одной стратегии не должен превышать 512 (иначе окно ничего не ограничивает) |
| покрытие, % | доля символов документов, попавшая в чанки. Считается по объединению интервалов, поэтому перекрытие `fixed` не удваивает покрытие. У `fixed` — 100 %, у `structural` — меньше там, где между секциями есть модульный код |
| структура, % | доля чанков с заголовком секции: у `fixed` — 0, у `structural` — большая |
| precision@k | доля релевантных среди первых k попаданий (релевантность — «источник входит в ожидаемые для этого запроса») |
| recall@k | сколько из всех релевантных чанков индекса попало в первые k |
| индексация, мс; эмбеддинги, мс | время прогона стратегии и время расчёта векторов |

**Гистограммы** (два графика рядом) показывают распределение размеров чанков по
бакетам `0-128`, `129-256`, `257-384`, `385-512`, `513+`. У `fixed` почти всё в
последних двух бакетах, у `structural` — размазано по всем: это визуальное
подтверждение σ.

**Примеры чанков** (по одной колонке на стратегию) — первые пять чанков с
документом, секцией и числом токенов: видно, что `fixed` начинает чанк там, где
кончилось окно, а `structural` — на заголовке раздела.

**Тестовые запросы** — пять раскрывающихся блоков: вопрос, ожидаемые документы
(ground truth из домена) и по три попадания каждой стратегии с оценкой близости.

## 6. Ручной поиск

Ниже раздела — форма «Поиск по индексу»: запрос, стратегия (`fixed`/`structural`) и
топ-k (1…20). Кнопка «🔎 Найти» показывает таблицу попаданий (ранг, оценка,
документ, заголовок, секция, токенов) и полный текст каждого чанка.

Через API то же самое:

```bash
curl "http://127.0.0.1:8000/indexing/search?query=переходы%20состояния%20задачи&top_k=3&strategy=structural"
```

Полезно помнить:

* **пустой индекс — не «ничего не нашлось», а 409**: сначала выполните индексацию;
* **пустой запрос — 400**, `top_k` вне 1…20 — 422;
* поиск по `structural` обычно точнее на «про что этот раздел», по `fixed` — на
  «где встречается такая фраза»: сравните оба на одном запросе.

## 7. Как интерпретировать метрики (коротко)

* **Чанков больше — не значит лучше.** Больше чанков = точнее локализация фрагмента,
  но и больше вычислений и шума в выдаче.
* **σ и максимальный размер** — про однородность. Ровные чанки (маленькая σ) удобны
  для бюджета контекста; неровные (большая σ) лучше сохраняют смысл, потому что не
  рвут раздел.
* **Покрытие** — про полноту: если у стратегии оно заметно ниже 100 %, часть
  документа в индекс не попала (у `structural` это модульный код между секциями).
* **Структура** — про метаданные: строка «секция» в попадании появляется только у
  стратегии, которая её знает.
* **precision@k / recall@k** считаются по пяти запросам и ожидаемым документам.
  Низкий recall при высоком precision означает «нашлось верное, но мало»: помогает
  увеличить `top_k` или разбить запрос иначе.
* **Время** важнее на больших наборах: сравнение стратегий по времени имеет смысл
  только при одинаковом числе эмбеддингов.

## 8. Пять сценариев проверки

Их прогоняет `scripts/indexing_demo.py`, и каждый отвечает на содержательный вопрос:

| № | Сценарий | Что доказывает | Команда |
|---|---|---|---|
| 1 | Полный демо-прогон | обе стратегии дают непустые индексы, метрики сравнения и пять запросов с попаданиями есть | `uv run python scripts/indexing_demo.py` |
| 2 | Одиночная стратегия | индексация только `fixed` работает: чанки есть, файл индекса создан, запуск завершён | то же (сценарий входит в прогон) |
| 3 | Поиск по индексу | запрос даёт непустой результат с метаданными, порядок попаданий не нарушает убывания оценки | то же |
| 4 | Качество поиска на обеих стратегиях | печатает топ-3 и precision@3 по ожидаемым источникам — видно, какая стратегия ближе | то же |
| 5 | Перезапуск без переиндексации | новый сервис читает индексы с диска: статистика не меняется, поиск даёт те же чанки | то же |

Офлайн-вариант (без сети и весов модели, качество поиска не показательно):

```bash
uv run python scripts/indexing_demo.py --stub-embedder
```

Код возврата 1, если хоть один сценарий не прошёл: прогон годится для автоматики.
После прогона читайте отчёт `docs/reports/indexing_demo.md` — в нём таблица
сравнения, распределение размеров чанков, примеры чанков, результаты пяти запросов,
вывод по каждому сценарию и список артефактов.

Автотесты дня:

```bash
uv run pytest -q                                   # весь набор дня
uv run pytest -q tests/unit                        # только чистые модули (быстро)
uv run pytest -q tests/integration/test_indexing_service.py     # служба индексации
uv run pytest -q tests/integration/test_indexing_restart.py     # сценарий 5 отдельно
uv run pytest -q tests/e2e/test_indexing_api.py                 # контракт /indexing
```

Тесты не ходят в сеть и не грузят настоящую модель: эмбеддер подменён фейком на
хешах слов, а `EmbeddingService._load` в тестах запрещён (случайная загрузка весов =
падение теста).

## 9. Переиндексация и очистка

Важно: **прогон дописывает индекс, а не перестраивает**. Поэтому после изменения
документов (например, правки README) порядок такой:

1. пересобрать набор: `uv run python scripts/prepare_documents.py --force`;
2. очистить индекс: кнопка «🧹 Очистить обе стратегии» в разделе или
   `curl -X POST http://127.0.0.1:8000/indexing/clear -H "Content-Type: application/json" -d "{\"strategy\":\"all\"}"`;
3. запустить демо-индексацию заново.

Если этого не сделать, чанки просто удвоятся: старые и новые попадут в один индекс, и
ответы поиска начнут дублироваться. Рост виден в статистике (`chars` чанков) и в
истории запусков — она в разделе ниже прогресса, там же детали любого запуска с
метриками.

Что хранится где:

| Артефакт | Где | В Git |
|---|---|---|
| документы | `day21/documents/` + `manifest.json` | нет |
| индексы FAISS | `day21/index/fixed.index`, `index/structural.index` | нет |
| кэш весов модели | `day21/index/models/` | нет |
| метаданные чанков и журнал прогонов (приложения и скрипта) | `day21/agents.db` (`document_chunks`, `index_runs`) | нет |
| снимок интерфейса | `day21/docs/reports/indexing_ui.png` | да |

Один важный момент: **скрипт и приложение пишут в одну БД и одни файлы индексов**.
Поэтому после прогона `scripts/indexing_demo.py` поиск в интерфейсе сразу работает —
и наоборот, индексация из интерфейса видна скрипту. Чтобы это было видно и в
цифрах, `GET /indexing/stats` отдаёт `index_vectors` рядом с `chunks`: если векторов
больше, чем строк, индекс и метаданные разошлись — лечится очисткой индекса.

Снимок раздела делает отдельный скрипт (он поднимает бэкенд и Streamlit, нажимает
кнопку демо и ждёт таблицу сравнения):

```bash
uv run playwright install chromium          # один раз
uv run python scripts/indexing_ui_shot.py   # положит PNG и не помешает, если браузера нет
```

## 10. Частые ошибки и что делать

| Симптом | Причина | Что делать |
|---|---|---|
| «Модель эмбеддингов не загрузилась … задайте DAY21_EMBEDDING_MODEL» | нет сети или веса ещё не скачаны | подключиться к сети; либо прогнать `scripts/indexing_demo.py --stub-embedder`; либо указать другую модель в `DAY21_EMBEDDING_MODEL` |
| Первый прогон идёт очень долго | скачивание весов (~470 МБ) и расчёт векторов на CPU | подождать; прогресс видно в счётчике эмбеддингов; следующие прогоны быстрее |
| `409` на `GET /indexing/search` | индекс ещё не построен | выполнить индексацию (кнопка демо или `POST /indexing/run`) |
| `400` «документов не нашлось» | `documents/` пуст, а источники недоступны | `uv run python scripts/prepare_documents.py --force`; проверить, что папка дня содержит нужные файлы репозитория |
| `400` «Неизвестная стратегия» | опечатка в `strategy` | допустимы только `fixed` и `structural` (а у очистки — ещё `all`) |
| В статистике чанков стало вдвое больше | прогон дописывает индекс | очистить индекс и прогнать заново (см. §9) |
| Поиск находит не то | мало чанков, плохой запрос или заглушка-эмбеддер | проверить `GET /indexing/stats` (есть ли чанки), попробовать другую стратегию и другой `top_k`; убедиться, что прогон был с настоящей моделью |
| Раздел «📦 Индексация» не появляется | устаревший процесс Streamlit или бэкенд не отвечает | перезапустить интерфейс/бэкенд; проверить `curl http://127.0.0.1:8000/` |
| `python scripts/indexing_demo.py` не находит пакеты | запуск не из папки дня | запускать из `day21/` (скрипты сами добавляют корень дня, но `.env` и БД ищутся относительно `cwd`) |

Быстрая диагностика одним запросом:

```bash
curl "http://127.0.0.1:8000/indexing/stats"     # есть ли чанки и файлы индексов
curl "http://127.0.0.1:8000/indexing/status"    # чем закончился последний прогон и почему
```
