# Рабочий процесс дня: от сырого задания до коммита

Три ступени для сложной задачи (эталон маршрута — этот день, `day21/`).
Простые задачи (кнопка, текст, правка документации) можно выполнять без
архитектурной ступени — сразу к исполнению.

```
1. Сырое задание          2. Архитектурный план         3. Исполнение и фиксация
   из челленджа      →       ARCHITECT_PROMPT.md    →    omp.sh (day21/)
   (размытое ТЗ)             в отдельном чате            commit + tag dayN
                             с DeepSeek                 + документация
```

| Ступень | Что делаем | Инструмент |
|---|---|---|
| 1. Задание | Берём текст задания дня из челленджа как есть: цель, критерии, ограничения | — |
| 2. План | Прогоняем задание через шаблон [`ARCHITECT_PROMPT.md`](../ARCHITECT_PROMPT.md) в **отдельном** чате с DeepSeek: получаем декомпозицию, DoD, пошаговый план, риски и план Б, проверки, команды фиксации | DeepSeek (вне omp) |
| 3. Исполнение | Передаём структурированный план в omp.sh. Если план уже структурирован — исполняем напрямую, без повторного планирования | omp.sh в папке `day21/` |
| 4. Фиксация | Обновляем документацию (только текущее состояние), коммитим, ставим тег дня | `git commit`, `git tag dayN` |

Почему план идёт отдельной ступенью: размытое ТЗ даёт размытый DoD, и агент
начинает решать «похожую» задачу вместо поставленной. Структурированный план
фиксирует цель и критерии **до** первой правки файлов, поэтому исполнение
сводится к проверке пунктов плана.

Связанные правила: [`AGENTS.md`](AGENTS.md) (раздел «Рабочий процесс нового
дня») и [`.omp/RULES.md`](.omp/RULES.md) (sticky-строка про архитектурный этап).
