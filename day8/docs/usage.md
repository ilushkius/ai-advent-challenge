# Инструкция по установке и использованию — День 8

Проект состоит из двух процессов: **бэкенд** FastAPI (порт `8000`) и
**фронтенд** Streamlit (порт `8501`). Диалоги агентов и метрики токенов
хранятся в SQLite (`day8/agents.db`) на бэкенде и **переживают его
перезапуск**. День 8 добавляет контроль токенов: каждый запрос считается
(tiktoken), метрики сохраняются и показываются в панели «📊 Токены диалога», а
при переполнении контекста агент автоматически сокращает историю.

## 1. Установка зависимостей

Нужен Python 3.10+ (разрабатывалось на 3.14). Все команды — из папки `day8/`.

```bash
cd day8
python -m venv .venv                       # Windows
# python3 -m venv .venv                    # Linux/macOS
.venv/Scripts/python -m pip install -r requirements.txt   # Windows
# .venv/bin/python -m pip install -r requirements.txt     # Linux/macOS
```

Проверка установки:

```bash
.venv/Scripts/python -c "import fastapi, uvicorn, streamlit, openai, requests, sqlalchemy, tiktoken; print('ok')"
```

## 2. Переменные окружения: ключ DeepSeek

Ключ читает только **бэкенд** (фронтенду он не нужен). Порядок поиска:
`day8/.env` → переменная окружения `DEEPSEEK_API_KEY`.

Способ 1 — файл `day8/.env` (рекомендуется; `.env` в git не попадает):

```bash
copy .env.example .env        # Windows
# cp .env.example .env        # Linux/macOS
```

Затем отредактируйте `day8/.env`: подставьте реальный ключ вместо
`вставьте-сюда-ваш-ключ`:

```
DEEPSEEK_API_KEY=sk-...
```

Способ 2 — переменная окружения:

```powershell
# PowerShell
$env:DEEPSEEK_API_KEY = "sk-..."
```

> Без ключа приложение работает: создание/список/удаление/очистка истории — без
> ограничений; генерация возвращает понятную ошибку 502 «Ключ API не задан».

## 3. Запуск

Терминал 1 — бэкенд (из папки `day8/`): при старте создаётся `agents.db` и
восстанавливаются агенты с историей.

```bash
.venv/Scripts/python -m uvicorn backend.main:app --port 8000
```

Проверка: <http://127.0.0.1:8000/docs> (Swagger) или
`curl.exe http://127.0.0.1:8000/agents` → `[]`.

Терминал 2 — фронтенд (из папки `day8/`):

```bash
.venv/Scripts/python -m streamlit run app.py
```

Откройте <http://localhost:8501>. Если бэкенд на другом адресе — задайте
`DAY8_BACKEND_URL` перед запуском фронтенда (по умолчанию
`http://127.0.0.1:8000`).

## 4. Сценарии использования

### 4.1. Создать агента

В боковой панели заполните форму «➕ Новый агент» (имя, модель, температура,
системный промпт, max_tokens) и нажмите «Создать агента». Агент появится в
списке с подписью `имя · модель · N сообщений` (у нового — 0).

Через API: `curl.exe -X POST http://127.0.0.1:8000/agents -H
"Content-Type: application/json" -d "{\"name\":\"Конспектёр\"}"` → в ответе
`agent_id` (далее `<ID>`).

### 4.2. Вести чат

Выберите агента в списке и пишите сообщения внизу → «🚀 Отправить». Каждое
сообщение показывается в чате с ролью («🧑 Вы» / «🤖 Ассистент») и добавляется в
историю агента. Следующий ответ модели строится по **всему** диалогу — агент
помнит, о чём говорили ранее.

### 4.3. Очистить историю

Кнопка «🧹 Очистить историю» удаляет диалог агента из SQLite (`DELETE
/agents/{id}/history`). Агент и его конфигурация остаются; новый диалог
начинается с нуля.

### 4.4. Демонстрация «диалог переживает рестарт» (для видео)

1. Запустите бэкенд и фронтенд, создайте агента и напишите 3–4 сообщения.
2. Покажите историю в интерфейсе и в SQLite (п. 4.5).
3. Остановите бэкенд (Ctrl+C).
4. Запустите бэкенд снова: `uvicorn backend.main:app --port 8000`.
5. Обновите страницу фронтенда и продолжите диалог — агент помнит предыдущие
   сообщения и отвечает с учётом контекста.

### 4.5. Панель «📊 Токены диалога» и демонстрация переполнения контекста (для видео)

Под шапкой выбранного агента интерфейс показывает панель токенов:

- **счётчики**: токенов использовано за диалог (сумма `total_tokens` всех
  ходов), число запросов, стоимость ($ по приблизительным тарифам модели);
- **индикатор контекста**: прогресс-бар «занято X из Y», остаток до лимита
  модели (`deepseek-chat` — 8000, `deepseek-reasoner` — 32000). Если осталось
  меньше 10% — жёлтое предупреждение;
- **рост токенов**: линейный график накопленной суммы токенов по запросам и
  таблица записей `token_usage` (время, запрос/ответ/всего/история/оценка
  ответа, стоимость).

Сценарий для видео:

1. Создайте агента `deepseek-chat` и задайте 2–3 обычных вопроса — в панели
   растут счётчик, индикатор, график и таблица.
2. Отправьте **очень длинное сообщение** (скопируйте в поле ввода большой текст,
   например ~6–7 тыс. символов) — индикатор уходит в красную зону, появляется
   предупреждение «Контекст почти заполнен».
3. Отправьте ещё одно длинное сообщение — агент **автоматически сокращает
   историю**: удаляет самые старые ЦЕЛЫЕ пары `user`+`assistant`, пока контекст
   не влезет в лимит. Вверху появляется сообщение «⚠️ Контекст был переполнен:
   удалено N самых старых сообщений», чат показывает сокращённую историю.
4. Покажите таблицу/график в панели и записи в SQLite (`token_usage`,
   раздел 4.6) — видно, что метрики ходов сохранены, а старые сообщения удалены.

Если даже при пустой истории сообщение длиннее лимита — генерация возвращает
понятную ошибку «Сообщение длиннее лимита контекста модели…», история не
меняется.

### 4.6. Просмотр SQLite

Покажите содержимое базы (Python встроен — отдельный `sqlite3` не нужен), из
папки `day8/`:

```bash
python -c "import sqlite3; con = sqlite3.connect('agents.db'); \
print('AGENTS:'); [print(' ', r) for r in con.execute('select agent_id, name from agents')]; \
print('MESSAGES:'); [print(' ', r) for r in con.execute('select id, agent_id, role, content from messages order by id')]; \
print('TOKEN_USAGE:'); [print(' ', r) for r in con.execute('select id, agent_id, prompt_tokens, completion_tokens, total_tokens, history_tokens, response_tokens, cost from token_usage order by id')]"
```

Или откройте `day8/agents.db` любым SQLite-клиентом/расширением браузера.

## 5. FAQ и возможные проблемы

| Проблема | Решение |
| --- | --- |
| Фронтенд пишет «Бэкенд недоступен» | Запустите uvicorn (раздел 3) и нажмите «🔄 Обновить список». `requests` не ходит через браузер, CORS не при чём. |
| «Порт 8000 занят» | Остановите процесс или смените порт: `--port 8001` у uvicorn и `DAY8_BACKEND_URL=http://127.0.0.1:8001` у фронтенда. |
| Генерация: «Ключ API не задан» (502) | Создайте `day8/.env` или задайте `DEEPSEEK_API_KEY` (раздел 2). Ключ читается на каждый запрос — рестарт не нужен. |
| DeepSeek отвечает ошибкой/таймаутом | Проверьте сеть и лимиты аккаунта (429). Ошибка показана в UI; история не изменяется — повторная отправка безопасна. |
| Агент «забыл» системный промпт после правки | Системный промпт — конфигурация агента (таблица `agents`), меняется при создании; реплики диалога хранятся отдельно. |
| Диалог переполняет лимит контекста (автообрезка) | Это штатное поведение дня 8: самые старые целые пары удаляются автоматически, агент предупреждает (сколько сообщений удалено). Полный сброс — «🧹 Очистить историю». |
| Почему в панели «оценки», а не точные токены? | Точные числа запроса/ответа берутся из `usage` DeepSeek; `history_tokens`/`response_tokens` — локальные оценки tiktoken (`cl100k_base`, приближение к токенизатору DeepSeek). |
| Лимиты 8000/32000 меньше реального контекста DeepSeek? | Да, значения демонстрационные (взяты из задания), реальный контекст API шире (~64K). Лимиты — константы `MODEL_TOKEN_LIMITS` в `day8/backend/config.py`, увеличиваются правкой одной строки. |
| Стоимость в панели совпадает с реальным счётом? | Приблизительно: тарифы — константы `MODEL_PRICES` в `config.py` (обновляйте под актуальные цены platform.deepseek.com). |
| `deepseek-reasoner`: ответы длиннее, чем `response_tokens` | API считает в `completion_tokens` и скрытые рассуждения (reasoning); `response_tokens` оценивает только видимый текст ответа. |
| Очень длинный диалог, старые сообщения потерялись | Автообрезка удаляет сообщения необратимо (требование демо). Чтобы не терять контекст — поднимите лимит в `config.py` или задавайте более короткие вопросы. |
| `agents.db` появился в папке, это нормально? | Да, это БД приложения. Она в `.gitignore` (`*.db`) и в git не попадает. |
| `deepseek-reasoner` игнорирует температуру | Поведение провайдера: модель рассчитана на reasoning. Используйте `deepseek-chat`, если важна температура. |
