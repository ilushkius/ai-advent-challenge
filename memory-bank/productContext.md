# Product Context — зачем проект существует и как работает

> Проблемы, которые решает проект, пользовательские сценарии и UX-цели.

## Проблема, которую решает проект

Автор изучает LLM/prompt-engineering на практике: чтения документации недостаточно,
нужны **живые эксперименты** с реальным API. Каждый день челленджа отвечает на
конкретный практический вопрос:

- **День 1.** Как подключиться к DeepSeek из кода и получить потоковый ответ?
  (консольный чат, безопасный ввод ключа).
- **День 2.** Почему модель отвечает по-разному на один и тот же промпт и как этим
  управлять: `temperature`, `seed`, `max_tokens`, `stop`, JSON-режим.
- **День 3.** Почему LLM ошибаются в простых задачах («куры и кролики»: 35 голов,
  94 ноги) и как техники рассуждения (CoT, мета-промпт, консилиум экспертов) меняют
  качество ответа.

Дополнительно проект решает задачу **наглядной демонстрации**: каждый запуск
показывает полную цепочку «запрос → параметры → ответ → метаданные», что удобно для
самообучения, видео и документации.

## Как проект работает с точки зрения пользователя

**День 1 (консоль):**
1. Запуск `python deepseek_chat.py`.
2. Скрипт сам находит ключ (`.env` → env-переменная → скрытый ввод `getpass`).
3. Пользователь печатает вопрос и получает **потоковый** ответ `deepseek-chat`
   (печать кусочками, как в онлайн-чате). Выход — `exit` / `выход`.

**День 2 и 3 (браузер, Streamlit):**
1. `streamlit run app.py` — открывается веб-страница.
2. В sidebar выбираются настройки: модель, режим (текст/JSON), `max_tokens`,
   `temperature`, seed, stop-строки; в Дне 3 — ещё «способ рассуждения».
3. Кнопка «🚀 Запустить запрос» → вызов DeepSeek, затем:
   - вкладка **«Результат»**: цветные теги `finish_reason`, счётчик токенов, время,
     ответ модели (в JSON-режиме парсится и красиво показывается через `st.json`);
   - вкладка **«Технический лог»**: что именно ушло в API (endpoint, messages,
     параметры), для мета-промпта — оба этапа (Шаг А и Шаг Б), таблица
     «что делает параметр», готовый JSON для копирования.

## Сценарии использования

- Изучение влияния одного параметра: всё фиксируется, меняется только он.
- Сравнение стратегий рассуждения на **одной и той же** задаче.
- Запись обучающего видео: технический лог дублируется JSON-блоком для показа.
- Проверка детерминизма: одинаковые `seed` + `temperature` + промпт → одинаковый ответ.

## UX-цели (паттерны, заложенные в код)

- Все подписи, `help=`-подсказки и предупреждения — по-русски и объясняют смысл.
- Результат последнего запуска живёт в `st.session_state` и не пропадает при rerun.
- Ошибки API показываются понятным сообщением через `st.error`, а не traceback'ом.
- Пустой ввод/отсутствие ключа отсекаются до вызова API с конкретной инструкцией.
