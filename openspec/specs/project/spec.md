# Project Specification

## Purpose

Целевой документ-«визитка» проекта ai-challenge: персональный учебный челлендж,
в котором каждый день выполняется одно практическое задание по изучению LLM и
промпт-инжиниринга на реальном API DeepSeek. Здесь зафиксированы цель, аудитория,
границы и сквозные требования проекта.

## Requirements

### Requirement: Ежедневные самодостаточные артефакты
Каждый день челленджа SHALL быть реализован как отдельная, изолированная папка
`dayN/` с собственным исполняемым файлом (`app.py` или скриптом),
`requirements.txt` и шаблоном `.env.example`, пригодная к запуску независимо от
других дней.

#### Scenario: Новый день не ломает старые
- GIVEN завершённые папки day1..dayN
- WHEN создаётся папка day(N+1) с собственными зависимостями
- THEN запуск приложений day1..dayN продолжает работать без изменений их кода

#### Scenario: Запуск изолированного приложения
- GIVEN папка конкретного дня с установленными зависимостями и ключом в `.env`
- WHEN пользователь запускает приложение из этой папки
- THEN приложение работает без обращения к файлам других дней

### Requirement: Обучающий русскоязычный интерфейс
Весь код, комментарии, подписи UI и пояснения SHALL быть написаны на русском
языке и носить обучающий характер («почему», а не только «что»).

#### Scenario: UI-подсказки объясняют смысл параметров
- GIVEN Streamlit-приложение дня 2 или 3
- WHEN пользователь наводит курсор на элемент управления параметром генерации
- THEN отображается русская help-подсказка, объясняющая, что делает параметр

### Requirement: Безопасное хранение API-ключа
Файлы `.env` SHALL игнорироваться git; в репозиторий SHALL попадать только
шаблоны `.env.example` без реальных секретов.

#### Scenario: Секрет не попадает в git
- GIVEN файл `.env` с реальным значением `DEEPSEEK_API_KEY`
- WHEN выполняется `git status` / `git add`
- THEN `.env` не отображается как отслеживаемый и не коммитится

### Requirement: Наглядная демонстрация для самообучения и видео
Каждое демо SHALL показывать «сырой» запрос с параметрами и метаданные ответа
(`finish_reason`, usage токенов, затраченное время), а в Streamlit-приложениях —
дополнительно готовый JSON для копирования.

#### Scenario: Технический лог совпадает с реальным вызовом
- GIVEN выполненный запрос в приложении дня 2 или 3
- WHEN пользователь открывает вкладку «Технический лог»
- THEN в логе отображаются endpoint, messages, параметры и метаданные ответа,
  идентичные отправленным в API

### Requirement: Управление параметрами генерации
Приложения дней 2–3 SHALL позволять менять `temperature`, `max_tokens`, `seed`
и stop-строки, а также включать строгий JSON-режим, и показывать влияние каждого
параметра на ответ.

#### Scenario: Эксперимент «один параметр за раз»
- GIVEN приложение дня 2
- WHEN пользователь фиксирует все параметры, кроме одного, и меняет только его
- THEN изменение ответа объясняется во вкладке результата/лога этим параметром

### Requirement: Проверка детерминизма
При одинаковых `seed`, `temperature` и промпте повторные запросы SHALL давать
идентичный ответ (детерминизм «символ в символ»).

#### Scenario: Повтор с тем же seed
- GIVEN приложение дня 2 и включённый чекбокс seed с фиксированным значением
- WHEN пользователь дважды запускает один и тот же промпт
- THEN ответы моделей совпадают полностью

### Requirement: Границы проекта
Проект SHALL оставаться лёгким учебным набором демо без БД, бэкенда,
авторизации, деплоя, CI и коммерческих целей; основная ценность — живые
эксперименты с реальным API и наглядные логи.

#### Scenario: Оценка объёма нового дня
- GIVEN планирование очередного дня челленджа
- WHEN объём выходит за рамки одного демо-приложения
- THEN день разбивается на несколько дней или часть выносится за scope
