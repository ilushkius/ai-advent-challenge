# Day4 Temperature Experiment Specification

## Purpose

Исследовательский день 4: систематическое сравнение ответов DeepSeek при
разных значениях параметра `temperature`, оформленное как документ
результатов с оценками и выводами, без изменения кода приложений дней 2–3.

## Requirements

### Requirement: Проведение эксперимента с одним меняющимся параметром

Эксперимент SHALL выполняться на модели `deepseek-chat` через endpoint
DeepSeek (`base_url` `https://api.deepseek.com`) тремя запросами с одним и
тем же user-промптом «короткий рассказ о роботе, который научился чувствовать
эмоции». Единственный меняющийся параметр SHALL быть `temperature` со
значениями 0, 0.7 и 1.2; `seed` SHALL не передаваться; `max_tokens` SHALL
быть достаточным, чтобы ответ не обрезался (`finish_reason = "stop"`).

#### Scenario: Идентичны все параметры, кроме temperature

- GIVEN три запроса эксперимента с одинаковым промптом и одинаковыми
  параметрами генерации
- WHEN значения `temperature` равны 0, 0.7 и 1.2
- THEN отличается только `temperature`, и все три ответа получены полностью
  (`finish_reason = "stop"`), без обрыва по лимиту токенов

### Requirement: Документ результатов

Эксперимент SHALL фиксироваться в `openspec/changes/day4/results.md` по
заданной структуре: полный запрос; для каждого значения `temperature` —
дословный ответ модели и анализ по критериям «Точность», «Креативность»,
«Разнообразие» с оценкой 0–10 и обоснованием; сводная сравнительная таблица;
выводы, для каких задач лучше подходит каждая настройка; личное наблюдение.

#### Scenario: Все разделы документа на месте

- GIVEN открытый файл `openspec/changes/day4/results.md`
- WHEN читатель просматривает документ
- THEN присутствуют разделы для `temperature` = 0, 0.7, 1.2 с дословными
  ответами, оценки всех трёх критериев лежат в диапазоне 0–10 и снабжены
  обоснованием, а также есть сравнительная таблица и раздел выводов

### Requirement: Git-трекаемая копия результатов

Поскольку папка `openspec/changes/` игнорируется в git, результаты
эксперимента SHALL дополнительно копироваться в отслеживаемый файл
`day4/results.md` с идентичным содержимым.

#### Scenario: Копия видна в git

- GIVEN созданный документ `openspec/changes/day4/results.md`
- WHEN его содержимое скопировано в `day4/results.md` и выполняется
  `git status`
- THEN новый файл `day4/results.md` отображается как untracked, а его
  содержимое идентично документу в папке изменения

### Requirement: Код приложений не изменяется

Эксперимент SHALL не менять код `day1/`, `day2/`, `day3/` и `shared/`; все
вспомогательные файлы эксперимента (скрипт запуска, сырые ответы) SHALL
размещаться в папке изменения `openspec/changes/day4/`.

#### Scenario: Чистый git для приложений

- GIVEN выполненный и оформленный эксперимент
- WHEN выполняется `git status --short` по файлам `day1/`, `day2/`, `day3/`
  и `shared/`
- THEN отсутствуют какие-либо изменения отслеживаемых файлов этих дней
