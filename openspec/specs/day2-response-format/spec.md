# Day2 Response Format Specification

## Purpose

День 2 челленджа: Streamlit-приложение «Формат ответа» (`day2/app.py`), которое
позволяет управлять генерацией DeepSeek: `temperature`, `max_tokens`, `seed`,
stop-строки и строгий JSON-режим, и наглядно показывает их влияние. Реализовано
и проверено (коммит `9f3d20d`, рефакторинг на `shared/` в `5aa6898`).

## Requirements

### Requirement: Управление параметрами генерации
Приложение SHALL предоставлять в sidebar настройки: выбор модели
(`deepseek-chat`/`deepseek-reasoner`), режим ответа («Обычный текст»/«Строгий
JSON»), `max_tokens` (10–3000), `temperature` (0.0–2.0), опциональный `seed`
(целое ≥ 0, передаётся только при включённом чекбоксе) и stop-строки
(разделяются запятыми).

#### Scenario: Сборка параметров по настройкам
- GIVEN пользователь задал настройки в sidebar
- WHEN он нажимает «🚀 Запустить запрос»
- THEN в API уходит запрос ровно с выбранными параметрами; выключенный seed
  отсутствует в параметрах

### Requirement: Вкладка «Результат»
Приложение SHALL показывать во вкладке «Результат»: цветной тег и расшифровку
`finish_reason`, счётчики токенов, затраченное время и ответ модели — в JSON-
режиме распарсенным через `st.json`, в текстовом — экранированной карточкой.

#### Scenario: Уведомление об обрезанном ответе
- GIVEN ответ модели с `finish_reason = "length"`
- WHEN пользователь смотрит вкладку «Результат»
- THEN приложение предупреждает, что ответ обрезан лимитом `max_tokens`, и
  советует увеличить ограничение

### Requirement: Вкладка «Технический лог»
Приложение SHALL показывать во вкладке «Технический лог»: что именно ушло в API
(endpoint, messages, параметры), метаданные ответа (`finish_reason` с
расшифровкой, время, usage), таблицу «что делает параметр» и готовый JSON для
копирования.

#### Scenario: Копируемый JSON лога
- GIVEN выполненный запрос
- WHEN пользователь открывает «📋 JSON для копирования»
- THEN отображается полный JSON запроса и метаданных, который можно скопировать
  для видео/документации

### Requirement: Валидации до вызова API
Приложение SHALL отсекать пустой промпт и отсутствие подходящего ключа до вызова
API, показывая конкретную инструкцию, а не traceback.

#### Scenario: Пустой промпт отклоняется
- GIVEN sidebar с корректным ключом и пустым полем промпта
- WHEN пользователь нажимает «🚀 Запустить запрос»
- THEN вызов API не выполняется и показывается понятное сообщение о пустом вводе
