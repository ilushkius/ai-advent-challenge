# Day1 Console Chat Specification

## Purpose

День 1 челленджа: консольный потоковый чат с моделью `deepseek-chat`
(`day1/deepseek_chat.py`). Знакомит с подключением к DeepSeek из кода, поиском
API-ключа и потоковой генерацией. Реализован и проверен (коммит `2b1d7fb`).

## Requirements

### Requirement: Потоковый вывод ответа
Скрипт SHALL отправлять ввод пользователя одним user-сообщением в модель
`deepseek-chat` с `stream=True` и печатать ответ кусочками по мере поступления
(как в онлайн-чате), без буферизации.

#### Scenario: Ответ печатается кусочками
- GIVEN запущенный скрипт и валидный ключ
- WHEN пользователь вводит вопрос
- THEN текст ответа появляется постепенно в одной строке и завершается переводом
  строки

### Requirement: Выход и защита от пустого ввода
Скрипт SHALL завершать диалог по командам `exit`/`выход` (без учёта регистра) и
SHALL пропускать пустой ввод, не отправляя его в API.

#### Scenario: Выход по команде
- GIVEN запущенный чат
- WHEN пользователь вводит `exit` или `выход`
- THEN скрипт печатает прощание и завершает работу

### Requirement: Понятная обработка ошибок API
При ошибке сети, неверном ключе или другой ошибке запроса скрипт SHALL показать
понятное сообщение об ошибке и продолжить диалог, а не падать.

#### Scenario: Сбой запроса не прерывает чат
- GIVEN запущенный чат и недоступная сеть
- WHEN пользователь задаёт вопрос
- THEN выводится сообщение «Произошла ошибка: …» и цикл диалога продолжается

### Requirement: Отсутствие истории диалога
Скрипт SHALL отправлять каждую реплику отдельным user-сообщением без накопления
истории беседы (ограничение дня 1, зафиксировано как известное ограничение).

#### Scenario: Модель не помнит предыдущий вопрос
- GIVEN запущенный чат
- WHEN пользователь задаёт второй вопрос, ссылаясь на первый
- THEN модель не имеет контекста предыдущего обмена, так как история не хранится
