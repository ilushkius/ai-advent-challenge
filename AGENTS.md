# AGENTS.md — архитектурные цели проекта ai-challenge

Этот файл агент **omp.sh** читает на старте вместе с `.clauderules`. Здесь —
целевая архитектура новых приложений и правила её реализации. Общие конвенции
проекта, стек и команды проверки — в `.clauderules`.

## Архитектурные цели

1. **Явная стейт-машина на Python.** Логику новых приложений описываем как
   конечный автомат: состояния, события, переходы. Никакой разбросанной логики
   в `if/elif` по всему коду — переходы централизуются в одном месте.
2. **Состояния и события — через `enum.Enum`.** Состояния — члены `enum.Enum`
   (например, `IDLE`, `LOADING`, `DONE`, `ERROR`), а не «магические» строки.
   События — тоже `Enum`. Значения — строковые/читаемые, чтобы попадать в UI и
   в лог без дополнительного маппинга.
3. **Переходы — паттерном State.** Каждое состояние — отдельный класс с общим
   интерфейсом (например, `handle(event)`), возвращающий следующее состояние.
   Стейт-машина хранит текущее состояние и делегирует ему обработку события.
   Классы состояний не зависят от UI (Streamlit/FastAPI) — только от домена.
4. **Тесты — через `pytest`.** Переходы стейт-машины покрываются модульными
   тестами: пакет `pytest`, файлы `test_*.py` рядом с кодом дня или в `tests/`.
   Тест пишется **до** реализации (TDD): сначала падает, потом зеленеет.
5. **Обратная совместимость.** `day1`–`day8` остаются как есть; новые правила
   применяются к новым дням (начиная с `day9/`) и к тому коду, который осознанно
   рефакторится.

## Где это уже реализовано

`day9/` — первый день, целиком построенный по этим правилам: стейт-машина
сжатия контекста (`backend/context_fsm.py`: `ContextState`/`ContextEvent` —
`Enum`, состояния — классы с `handle(event)`, неизвестное событие —
`UnknownContextEvent`) и автотесты `pytest` (`day9/tests/`, включая
параметризованную таблицу переходов и негативные сценарии). Чистая арифметика
«когда сжимать и что оставить» вынесена в `backend/context_policy.py` и
покрыта отдельными тестами — образец для новых дней.

## Правила работы с `Enum` и паттерном State

- Состояние и событие — только через `Enum`; никаких «сырых» строк и чисел.
- `Enum` — это идентификатор, а не логика: поведение живёт в классах-состояниях.
- Диаграмма переходов однозначна: у каждого события в конкретном состоянии —
  ровно один результат.
- Неизвестное событие в состоянии → явная ошибка (или осознанный безопасный
  `IGNORE`), но не «тихое» зависание.
- Классы состояний — маленькие, тестируемые, без побочных эффектов на импорте.
- Стейт-машина отделена от транспорта: Streamlit/FastAPI лишь транслируют
  события и отображают состояние.

## Структура файлов

Правила — целевые для новых дней (`day13/` и далее) и для кода, который
осознанно рефакторится. Снимки прошлых дней под них не переписываются (см.
ниже «Известные расхождения со снимками»).

- **Любой `.py` — не больше 400 строк.** Файл подошёл к ~350 строкам — дели на
  модули по доменам, не дожидаясь 401-й строки.
- **Streamlit UI — только в папке `ui/`**, разбитый по секциям. Обязательный
  минимум: `ui/sidebar.py` (боковая панель), `ui/chat_section.py` (основная
  область), `ui/memory_panels.py` (панели слоёв памяти), `ui/profile_section.py`
  (раздел «Профиль пользователя»), `ui/api_client.py` (HTTP-клиент к бэкенду).
  Не влезает в 400 строк или распадается на два домена — рядом кладётся ещё один
  модуль `ui/<domain>.py` (в `day12/` так появились `ui/common.py`,
  `ui/context_panels.py`, `ui/profile_comparison.py`).
- **`app.py` — только точка входа (≤ 100 строк):** `st.set_page_config`,
  инициализация состояния и вызовы секций. Логики панелей, запросов и
  форматирования в `app.py` нет.
- **FastAPI — эндпоинты в `backend/routers/` по доменам:** `agents.py`,
  `memory.py`, `profiles.py`, `context.py`. Эндпоинт лежит в файле своего
  домена; пути внутри роутеров абсолютные (`/agents/...`), префиксы не вводятся.
- **`backend/main.py` — только создание `app` и подключение роутеров
  (≤ 80 строк):** `FastAPI(...)`, CORS, `lifespan`, `include_router(...)`.
  Помощники роутов — в отдельных модулях (в `day12/` — `backend/dependencies.py`).
- **SQLAlchemy-модели (таблицы) — в `backend/models/` по доменам:** `agent.py`,
  `memory.py`, `profile.py`, `context.py`. Свалки в одном `models.py` быть не
  должно.
- **Pydantic-схемы API — в `backend/schemas/` по доменам** (те же имена:
  `agent.py`, `memory.py`, `profile.py`, `context.py`). `schemas/__init__.py`
  реэкспортирует все имена, чтобы остальной код импортировал схемы из одного
  места.
- **Общие утилиты — из `shared/`, а не из папки дня:** клиент DeepSeek, база
  SQLAlchemy (`Base`, движок, фабрика сессий), подсчёт токенов (tiktoken),
  логирование. Код, не меняющийся между днями, обязан жить в `shared/` и между
  днями не дублироваться (`shared/deepseek_utils.py`,
  `shared/deepseek_client.py`, `shared/db_base.py`, `shared/token_counter.py`,
  `shared/logging_utils.py`).

Уточнение к `.clauderules` §3 («Один файл = одно приложение дня»): правило
описывает одностраничные демо (day2/day3/day5). В новых днях с бэкендом и UI
раскладка — по списку выше.

Проверка лимита строк (из папки дня; `.venv` исключён):

```powershell
.venv\Scripts\python -c "from pathlib import Path; print([(str(p), len(p.read_text(encoding='utf-8').splitlines())) for p in sorted(Path('.').rglob('*.py')) if '.venv' not in p.parts and len(p.read_text(encoding='utf-8').splitlines()) > 400])"
```

## Запрещено

- Складывать всю логику в один файл, если он превышает 400 строк.
- Создавать `utils.py` / `helpers.py` без чёткой доменной принадлежности —
  вместо этого `shared/<domain>.py` (или `<пакет>/<domain>.py`, если код
  относится к одному домену дня).
- Копировать один и тот же код в `dayN/` и `dayN+1/`, если он не меняется между
  днями: неизменяемый между днями код живёт в `shared/`.
- Менять код предыдущих дней (`day1/` … `dayN-1/`) — они являются снимками.
  Правка снимка — только по прямому запросу пользователя.

## Обязательно

- Перед началом работы посмотреть структуру `dayN-1/` и переиспользовать её
  паттерны: имена модулей, слои, конвенции тестов.
- Новая сущность — сразу определить её домен и положить в соответствующий
  модуль (`ui/`, `backend/routers/`, `backend/models/`, `backend/schemas/`,
  `shared/`), а не в «ближайший» файл.
- После реализации проверить, что ни один файл не превышает 400 строк (команда
  выше) и что лимиты `app.py` (≤ 100) и `backend/main.py` (≤ 80) соблюдены.
- Вести `STRUCTURE.md` в папке каждого нового дня: список модулей дня и
  назначение каждого в одну строку. Обновлять файл при добавлении модулей;
  `README.md` и `docs/` он не заменяет.
- Задачи по новым приложениям запускать в Plan Mode: сначала предложить
  структуру файлов (модули и их обязанности), дождаться утверждения, потом
  реализовывать.

## Известные расхождения со снимками

`day1/`–`day12/` — снимки: под правила структуры их не переписывают. Что уже
расходится с правилами (замерено 2026-09-15): монолитные `app.py` длиннее
400 строк в `day3/`, `day5/`, `day8/`, `day9/`, `day10/`, `day11/`; файлы сверх
400 строк есть в `day8/`–`day12/` (например, `day10/backend/agent.py` — 1140,
`day11/app.py` — 1566, `day12/backend/agent.py` — 1515); в `day12/` ORM-таблицы
лежат в `backend/tables.py`, а Pydantic-схемы — в `backend/models/` (по правилам
наоборот), и там же `backend/main.py` — 84 строки при лимите 80; ни в одном дне
нет `STRUCTURE.md`.

При конфликте «паттерн `dayN-1/`» и «правила структуры» приоритет у правил
структуры: паттерн повторяем, раскладку файлов делаем по правилам, а расхождение
отмечаем в `STRUCTURE.md` нового дня.

## Целевой стек и запуск

| Слой | Технология |
| --- | --- |
| Язык | Python 3.14+ (Windows, PowerShell) |
| UI демо | Streamlit ≥ 1.30 |
| API | OpenAI SDK → DeepSeek (`https://api.deepseek.com`) |
| Стейт-машина | `enum.Enum` + паттерн State (чистый Python) |
| Тесты | `pytest` |

```powershell
# из папки дня (CWD важен: .env ищется здесь)
pip install -r requirements.txt
streamlit run app.py          # UI
python -m pytest -q           # тесты
```
