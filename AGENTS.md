# AGENTS.md — архитектурные цели проекта ai-challenge

Этот файл агент **omp.sh** читает на старте вместе с `.clauderules`. Здесь —
целевая архитектура новых приложений и правила её реализации. Общие конвенции
проекта, стек и команды проверки — в `.clauderules`.

## Архитектурные цели

1. **Явная стейт-машина на Python.** Логику новых приложений описываем как
   конечный автомат: состояния, события, переходы. Никакой разбросанной логики
   в `if/elif` по всему коду — переходы централизуются в одном месте.
2. **Состояния и события — через `enum.Enum`.** Состояния — члены `enum.Enum`
   (например, `IDLE`, `LOADING`, `DONE`, `ERROR`), а не «магические» строки.
   События — тоже `Enum`. Значения — строковые/читаемые, чтобы попадать в UI и
   в лог без дополнительного маппинга.
3. **Переходы — паттерном State.** Каждое состояние — отдельный класс с общим
   интерфейсом (например, `handle(event)`), возвращающий следующее состояние.
   Стейт-машина хранит текущее состояние и делегирует ему обработку события.
   Классы состояний не зависят от UI (Streamlit/FastAPI) — только от домена.
4. **Тесты — через `pytest`.** Переходы стейт-машины покрываются модульными
   тестами: пакет `pytest`, файлы `test_*.py` рядом с кодом дня или в `tests/`.
   Тест пишется **до** реализации (TDD): сначала падает, потом зеленеет.
5. **Обратная совместимость.** `day1`–`day8` остаются как есть; новые правила
   применяются к новым дням (начиная с `day9/`) и к тому коду, который осознанно
   рефакторится.

## Где это уже реализовано

`day9/` — первый день, целиком построенный по этим правилам: стейт-машина
сжатия контекста (`backend/context_fsm.py`: `ContextState`/`ContextEvent` —
`Enum`, состояния — классы с `handle(event)`, неизвестное событие —
`UnknownContextEvent`) и автотесты `pytest` (`day9/tests/`, включая
параметризованную таблицу переходов и негативные сценарии). Чистая арифметика
«когда сжимать и что оставить» вынесена в `backend/context_policy.py` и
покрыта отдельными тестами — образец для новых дней.

## Правила работы с `Enum` и паттерном State

- Состояние и событие — только через `Enum`; никаких «сырых» строк и чисел.
- `Enum` — это идентификатор, а не логика: поведение живёт в классах-состояниях.
- Диаграмма переходов однозначна: у каждого события в конкретном состоянии —
  ровно один результат.
- Неизвестное событие в состоянии → явная ошибка (или осознанный безопасный
  `IGNORE`), но не «тихое» зависание.
- Классы состояний — маленькие, тестируемые, без побочных эффектов на импорте.
- Стейт-машина отделена от транспорта: Streamlit/FastAPI лишь транслируют
  события и отображают состояние.

## Целевой стек и запуск

| Слой | Технология |
| --- | --- |
| Язык | Python 3.14+ (Windows, PowerShell) |
| UI демо | Streamlit ≥ 1.30 |
| API | OpenAI SDK → DeepSeek (`https://api.deepseek.com`) |
| Стейт-машина | `enum.Enum` + паттерн State (чистый Python) |
| Тесты | `pytest` |

```powershell
# из папки дня (CWD важен: .env ищется здесь)
pip install -r requirements.txt
streamlit run app.py          # UI
python -m pytest -q           # тесты
```
