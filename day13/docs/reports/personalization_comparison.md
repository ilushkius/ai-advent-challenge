## Наблюдаемые эффекты профилей

| Проверка | Результат | Факт из ответа |
|---|---|---|
| Строгий технический: ответ держится у лимита 600 символов (constraints.max_response_length; допуск 1.5×, потому что модель соблюдает ограничение приблизительно) | ✅ да | 462 символов при лимите 600 |
| Строгий технический: ответ без markdown-разметки (preferences.format = plain text) | ✅ да | разметка: нет |
| Дружелюбный наставник: ответ в markdown (preferences.format = markdown) | ❌ нет | разметка: нет |
| Дружелюбный наставник: ответ подробнее, чем у строгого профиля (preferences.verbosity = подробно) | ✅ да | 644 против 462 символов |
| Оркестратор процесса: роли идут в порядке аналитик → разработчик → тестировщик (custom_instructions) | ✅ да | порядок в ответе: аналитик → разработчик → тестировщик |

Проверки стиля, формата и длины — это наблюдения, а не гарантии: модель вероятностная, и ограничение из профиля сдвигает ответ (промпт «жёсткое ограничение: весь ответ не длиннее N символов»), но не обязывает её соблюсти лимит символ в символ. Факт этого прогона: 462 символов при лимите 600 у строгого профиля против 644 символов у «подробного» — ограничение работает как управление объёмом, а не как обрезка текста. Проверки, которые обязаны выполняться всегда, — подстановка профиля в системный промпт (видно в разделе с промптами) и следование кастомной инструкции о порядке ролей.


## Вывод

Профиль — это часть системного промпта, а не подсказка в UI: один и тот же вопрос получает разные ответы по стилю (technical → friendly), формату (plain text → markdown), длине (кратко → подробно) и структуре (обычный ответ → разложенный по ролям аналитик → разработчик → тестировщик). Ограничения тоже работают как ограничения: max_response_length держит ответ в заданном пределе, forbidden_topics уводит разговор от запрещённых тем, required_disclaimers добавляет обязательную вставку.

cd day13
